# 現場疑難排解（免費版，講師用）

按**學員看到的症狀**排列。本版本很少有帳號或付費問題，
但較常出現檔案格式與副檔名問題，因為每個步驟都由學員手動完成。

---

## Lab 0：帳號 + 存檔練習

### 「雙擊 test.html 打開的是記事本，不是瀏覽器」

**全場最常見的問題，佔開場問題的一半以上。**

檔案其實叫 `test.html.txt`。Windows 記事本存檔時「存檔類型」預設是
「文字文件 (\*.txt)」，即使檔名包含 `.html`，仍會自動加上 `.txt`。

**修法：** 回存檔視窗，「存檔類型」下拉選單改選 **「所有檔案 (\*.\*)」**，再存一次。

**確認方法：** 檔案總管 → 上方「檢視」→ 打勾「副檔名」，這樣才看得到檔案真正的全名。
未開啟時，`test.html.txt` 在畫面上可能只顯示 `test.html`。

**建議：** 開場先帶全班開啟「顯示副檔名」，減少後續排查時間。

### 「Mac 開啟後顯示程式碼或格式不正確」

TextEdit 預設用 RTF（有格式的文件）存檔，貼進去的 HTML 語法會被格式化破壞。

**修法：** 開新檔案，**先按 `Shift+Cmd+T`**（製作純文字）再貼上，重新存一次。
已儲存成 RTF 的檔案請重新建立為純文字檔案。

**看什麼：** 文字編輯視窗上方有沒有格式列（字型、大小選單）。
有格式列 = 還在 RTF 模式，還沒切純文字。

### 「存檔按鈕按了沒反應／找不到存檔位置」

多半是存到了系統資料夾看不到的地方。**明確請學員存到桌面**，
後續都存到桌面，維持固定位置。

## 共同練習與個人專題（本機建置）

### 「畫面一片空白」

按 `F12` 打開瀏覽器主控台，看紅字，整段複製貼回 claude.ai：

```text
畫面是空白的，主控台出現這個錯誤：（貼上）請修好，給我完整程式碼
```

### 「重新整理資料就不見了」

某些瀏覽器對用「雙擊直接打開」的檔案（網址列開頭是 `file://`）會限制
`localStorage`。這是這個版本特有的問題，付費版因為用本機伺服器打開所以不會遇到。

**現場最快的修法：換 Chrome 或 Edge。** 大部分情況下换瀏覽器就解決了。

還是不行的話，讓學員知道：資料存不住不影響繼續往下走，
先完成畫面、新增與刪除功能；`localStorage` 的部分留到「延伸練習」再處理。

### 「它回答的程式碼中間寫『...』或『這裡省略』」

AI 回覆有時會省略部分內容。請回覆：

```text
你剛剛的程式碼被截斷了，請重新給我完整版本，不要用「...」帶過任何部分
```

應在 Lab 1 開場說明一次。提示詞範本已包含「請給我完整程式碼」，
學員自行增加需求時也需要保留這句。

### 「貼到記事本之後想改東西，不知道要怎麼弄」

引導學員用「全選蓋掉」的流程，不要教他們手動找特定那幾行改：

1. 回聊天視窗要新版本
2. 複製
3. 回記事本/文字編輯，`Ctrl+A`／`Cmd+A` 全選
4. 貼上蓋掉
5. 存檔（`Ctrl+S`／`Cmd+S`，不用重新選檔名，因為檔案已經存在過一次）
6. 回瀏覽器重新整理

## 個人專題：免費版特有問題

### 「AI 只給修改片段」

要求以目前完整程式碼為基礎，回傳更新後的完整 `index.html`，不要自行拼接片段。

### 「第二輪覆蓋後，第一輪可用版本不見了」

回 GitHub 找第一輪上傳的版本，複製完整內容回本機，再把第二輪需求縮小為一項修改。

### 「專題產生很多檔案或要求安裝套件」

要求改成單一 `project/index.html`、不使用套件與建置工具。外部整合列入下一版。

## 備用案例：每日自動摘要（GitHub Actions）

跟付費版幾乎一樣，因為這一段本來就是純 GitHub 網頁操作，跟學員本機用什麼工具無關。

### 「Actions 分頁裡面是空的」

先問：**「兩個檔案都 Commit 了嗎？」** 檔名打錯（例如漏了 `.github/workflows/` 前綴，
或打成 `github/workflows/`，少了開頭的點）是最常見的原因——GitHub Actions
**只認 `.github/workflows/` 這個確切的路徑**，打錯一個字都抓不到。

**檢查方法：** 到 repo 首頁，點進 `.github` 資料夾，再點進 `workflows`，
確認 `digest.yml`真的在那裡。

### 「沒有 Run workflow 按鈕」

workflow 檔案裡缺 `workflow_dispatch`。回聊天視窗要修好的完整版本，
用「Edit this file」（鉛筆圖示）覆蓋掉舊內容。

### 「執行到最後顯示紅色 ✗，訊息裡有 permission 或 403」

缺 `permissions: contents: write`。跟前面一樣，回聊天視窗要修好的版本，
在 GitHub 上編輯覆蓋。

參考解：`../../instructor/reference/digest-workflow.yml` 和
`../../instructor/reference/fetch-digest.mjs`——**這兩個檔案跟付費版完全通用**，
GitHub Actions 不在乎檔案是怎麼被放上去的。

### 通用做法：把錯誤訊息貼回去

```text
我的 GitHub Actions 失敗了，錯誤訊息是：
（貼上）
請告訴我哪個檔案要改，並給我修好之後的完整內容
```

拿到回答後，回 GitHub 該檔案頁面，點右上角鉛筆圖示編輯，全選覆蓋，Commit。

## 備用案例：發布成公開網站

跟付費版完全一樣（純 GitHub 網頁操作），參見
`../../instructor/troubleshooting.md` 的「Lab 3」段落。唯一差別：

### 「首頁點連結，跳到 404」

多半是相對路徑寫錯，或首頁不小心存到某個資料夾裡而不是根目錄。

**檢查方法：** 到 repo 首頁最上層（不要點進任何資料夾），直接看得到
`index.html` 才對——如果 `index.html` 是在點進某個資料夾之後才看到，
代表存錯位置了，要重新用「Add file」存一次到根目錄。

## 任何時候

### 「我不知道自己複製到什麼、貼到哪裡了」

這是免費版最容易累積的混亂。**教學員一個固定習慣**：

> 「聊天視窗的答案 → 記事本/文字編輯（本機測試用）→ 滿意了才貼到 GitHub。」

三個地方各司其職，不要跳著來、不要在 GitHub 網頁上直接寫程式碼。

### 「修改後無法正常運作，而且不知道怎麼還原」

免費版沒有版本控制的即時安全網（付費版可以講「git 還原」），但 GitHub 網頁
本身仍然留有紀錄：

repo → **Commits** → 找到還能動的那一版 → 點進去看當時的檔案內容 → 複製回來。

**本機檔案無法正常運作**：回聊天視窗，貼「請重新給我一開始可正常運作的版本」，
只要聊天視窗還在同一個對話串，AI 通常記得前面說過的內容。

### 「我落後兩個 Lab 了」

不要讓他從頭追。跳到**當前** Lab，前面的成果課後再補。
每個 Lab 都有「需要追上進度？」區塊，請指出位置。

### 網路中斷

跟付費版一樣——claude.ai 完全依賴網路。開手機熱點給最需要的幾個人，
全場性斷網就改成講師示範，學員看。
