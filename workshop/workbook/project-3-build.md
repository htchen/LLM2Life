# 專題 3：分段實作、驗證與分享（50 分鐘）

免費版每次更新都要取得完整檔案：

> **指定一步 → 取得完整程式碼 → 全選舊內容 → 貼上 → 存檔 → 測試 → 上傳版本**

## 第一輪：完成核心流程（30 分鐘）

```text
這是我的專題簡述與實作計畫：（貼上內容）

現在只做第 1 步，製作成單一個 index.html。
請給我完整、可以直接存成檔案使用的程式碼，不要省略。
最後列出我要依照哪些操作驗證這一步。其他步驟先不要做。
```

將內容存成 `project/index.html`。實際測試後，把通過的版本上傳到 GitHub。

## 第二輪：增加下一項必要功能（15 分鐘）

```text
這是目前完整程式碼：（貼上）
現在進行計畫中的第 2 步，只修改這一步需要的內容。
請給我更新後的完整程式碼，不要只給片段。
最後列出新功能與原有功能各要測試什麼。
```

用新版本完整蓋掉舊檔案，存檔後重新測試，再上傳到 GitHub。

## 展示：互相使用（6 分鐘）

若已開啟 GitHub Pages，網址為：
`https://你的帳號.github.io/my-life-tools/project/`

不上台輪流講。兩人一組：

1. 交換網址（或 QR），**用對方的工具**三分鐘。不看說明、不聽解釋。
2. 使用者回報**一件做不到或看不懂的事**。製作者只記下來，不辯解。
3. 交換角色。
4. 各自把回報的那一件寫進「下一版」清單的第一項。

用一分鐘能說清楚的仍要準備：原本問題、縮小後的目標、如何驗證、下一版要增加什麼——
被抽到時要講，而且對方用過之後你會更知道該怎麼講。

## ✅ 最終檢查點

- [ ] 核心流程可以完整操作一次
- [ ] 三項驗收條件至少通過兩項
- [ ] GitHub 上看得到目前版本
- [ ] 我的工具被另一個人用過，對方回報的那一件事已寫進下一版清單
- [ ] 我能在一分鐘內說明問題、成果與下一步

未完成全部功能時，請保留可操作版本並記錄下一步，不要在最後階段同時增加多項功能。
