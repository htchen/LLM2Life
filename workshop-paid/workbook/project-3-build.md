# 專題 3：分段實作、驗證與分享（48 分鐘）

## 這一段結束時，你會有

- 一個可操作的最小版本
- 至少兩個經過驗證的版本紀錄
- 一段可以展示問題、成果與下一步的說明

---

## 實作循環

每一步都使用相同流程：

> **指定一步 → 實作 → 打開結果 → 依驗收條件測試 → commit → 下一步**

### 第一輪：完成核心流程（23 分鐘）

```text
這是我的專題簡述與實作計畫：（貼上內容）

請在 project/ 資料夾開始製作。現在只做第 1 步。
完成後幫我在瀏覽器打開，並告訴我要依照哪些操作驗證這一步。
其他步驟先不要做。
```

依照自己的驗收條件實際操作。測試通過後：

```text
第 1 步已經依照驗收條件測試通過。請 commit 這個版本，
commit 訊息清楚寫出完成的功能。先不要做下一步。
```

### 第二輪：增加下一項必要功能（15 分鐘）

```text
現在進行計畫中的第 2 步。只修改這一步需要的內容，
完成後打開結果，列出這一步與原有功能各要測試什麼。
```

測試新功能，也重新測一次原本的核心流程。通過後再 commit 並 push。

---

## 需要調整計畫時

實作後發現原計畫不合理，可以修改計畫，不需要勉強照原順序完成。

```text
實際看到第一版後，我發現：（描述觀察）
原本計畫中的第＿＿步需要調整為：（新的需求）
請先更新計畫並說明影響，等我確認後再修改檔案。
```

---

## 發布與展示準備（10 分鐘）

若專題是網頁，可以沿用 GitHub Pages。將 `project/` 加到首頁，或直接使用：

`https://你的帳號.github.io/my-life-tools/project/`

不上台輪流講。兩人一組：

1. 交換網址（或 QR），**用對方的工具**三分鐘。不看說明、不聽解釋。
2. 使用者回報**一件做不到或看不懂的事**。製作者只記下來，不辯解。
3. 交換角色。
4. 各自把回報的那一件寫進「下一版」清單的第一項。

被抽到時仍只說四件事：原本遇到什麼問題、目標縮小成什麼、如何操作並驗證、下一版最優先增加什麼。

## ✅ 最終檢查點

- [ ] 核心流程可以完整操作一次
- [ ] 三項驗收條件至少通過兩項；未通過的項目已記錄
- [ ] GitHub 上看得到分段 commit
- [ ] 我的工具被另一個人用過，對方回報的那一件事已寫進下一版清單
- [ ] 我能在一分鐘內說明問題、成果與下一步

未完成全部功能不代表專題失敗。只要範圍、目前結果與下一步都清楚，就已完成一次完整的專題流程。
