# 現場疑難排解（講師用）

按**學員看到的症狀**排列，不按技術分類，供講師直接比對畫面。

每一條的格式：症狀 → 30 秒內先問什麼 → 怎麼修。

---

## 開場 / Lab 0

### 「點 Code 分頁跳出要我升級」

**最常見，佔開場問題的一半以上。**

Claude Code 需要付費方案（Pro / Max / Team / Enterprise），免費帳號無法使用，沒有例外。

- 願意當場訂閱 → https://claude.com/pricing，約 3 分鐘，訂完要**重開桌面版**。
- 不願意或不能訂閱 → 立即安排兩人一組，避免繼續嘗試無法使用的功能。

> 講法建議：「這項功能需要付費方案。我會安排兩人共用一台電腦，並輪流操作。」

### 「Code 分頁一直轉圈 / 出現 403」

先問：**「你是不是用公司或學校的帳號登入？」**

- 是 → 多半是組織政策擋掉了。走 `claude.ai/code`，或兩人一組。
- 否 → 完全登出桌面版，重新登入一次，再重開 App。

### 「桌面版裝不起來 / 電腦不給我裝軟體」

走瀏覽器路線：https://claude.ai/code

注意這條路線的差別，要先跟學員講清楚，否則他會跟不上投影片：

- 需要先在 GitHub 上**建好 repo**（不能從空白開始）
- 檔案改在雲端，不在他的電腦裡
- 改完會產生一個分支，要按 **Create PR** 才會進 main

共同練習與個人專題在這條路線上要多一步：檔案不在本機，
**可以先開 GitHub Pages 查看成果**。建議在 Lab 0 完成 Pages 設定。

### 「Windows 上 Code 分頁說要裝 Git」

前往 https://git-scm.com/downloads/win，依安裝程式的預設步驟完成安裝，再**重開 Claude 桌面版**。

沒重開是最常見的後續問題——裝好了但 App 還沒看到。

### 「建 repo 時找不到 Public 選項 / 不小心建成 Private」

Public / Private 在建立頁面的下半部，很多人沒往下捲。

已經建成 Private 的話：repo 頁面 → **Settings** → 最下面 **Danger Zone** →
**Change repository visibility** → 改成 Public。

**免費帳號的 Private repo 不能開 GitHub Pages**，所以要在個人專題發布前處理。

## 共同練習：探究提問卡

### 「Claude 一直在執行，我不知道目前進度」

正常。它在讀檔案、寫檔案。告訴學員：

- 可以停：按停止鈕
- 可以插話：直接打字送出，它會把你的話納入
- **不用重來**：需要調整時直接補充需求

可在 Lab 開始時對全場說明一次。

### 「它做好了，但我打不開那個檔案」

不要教他們找檔案總管。直接讓 Claude 做：

```text
幫我在瀏覽器打開這個頁面
```

### 「資料重新整理就不見了」

localStorage 在某些瀏覽器用 `file://` 開啟時會被擋掉。讓 Claude 起一個本機伺服器：

```text
幫我開一個本機伺服器來打開這個頁面，這樣資料才存得住
```

### 「畫面一片空白」

請學員**按 F12 打開主控台，把紅色錯誤訊息完整複製**，貼回 Claude Code：

```text
畫面是空白的，主控台出現這個錯誤：
（貼上錯誤訊息）
請修好它
```

可對全場示範一次完整流程：取得錯誤訊息、貼回工具、修改後重新測試。

## 個人專題：發想與規劃

### 「題目需要登入、資料庫或很多外部資料」

先保留問題，但縮小課堂版本：單一使用者、單一頁面、使用範例資料或瀏覽器本機資料。
原本的整合需求列入下一版。

### 「必要功能列了很多項，無法決定先做什麼」

請學員回答：「如果只能保留一個完整操作流程，哪一個最能改善原本問題？」
必要功能最多三項，其餘移到「這次不做」。

### 「AI 列出的計畫只有技術名稱」

```text
請把每一步改寫成使用者可以操作與驗收的結果。
每一步都要寫：我要做什麼操作、應該看到什麼。不要只列技術名稱。
```

### 「第一輪時間快結束，還沒有可操作畫面」

縮小第一步，只保留一個輸入與一個可見輸出。停止加入配色、動畫與延伸功能。

### 「第二輪修改後原本功能失效」

先回到第一輪 commit。重新要求只增加一項功能，並列出原有核心流程的回歸測試。

## 備用案例：每日自動摘要

### 「Actions 分頁裡面是空的 / 找不到我的 workflow」

先問：**「你 push 上去了嗎？」**

多數是這個。workflow 檔案必須推上 GitHub，Actions 才看得到。本機存檔不算。

```text
把目前的改動 commit 並 push 到 GitHub
```

### 「沒有 Run workflow 按鈕」

workflow 檔案裡缺 `workflow_dispatch`。

```text
在 workflow 加上 workflow_dispatch，我要能手動按按鈕執行
```

### 「執行到最後一步顯示紅色 ✗，訊息裡有 permission 或 403」

缺寫入權限。這是 Lab 2 最常見的失敗。

```text
workflow 推不回 repo，請加上 permissions: contents: write
```

參考解：`shared/reference/digest-workflow.yml`

### 「綠色打勾了，但 repo 裡沒有新檔案」

常見原因是取得的內容為空，因此沒有檔案可以 commit。請他把執行紀錄貼回去：

```text
workflow 執行成功但沒有產生檔案，這是執行紀錄：
（貼上 log）
請找出原因並修好
```

### 通用做法：把錯誤訊息貼回去

Actions 失敗時，點進紅色的那一步，複製錯誤訊息，貼回 Claude Code：

```text
我的 GitHub Actions 失敗了，錯誤訊息是：
（貼上）
請修好它
```

現場至少示範一次如何查看錯誤訊息並重新測試。

## 備用案例：習慣儀表板與公開發布

### 「網址打開是 404」

依機率排序，逐項確認：

1. **才剛開 Pages** → 第一次要等 1–10 分鐘。這是最常見的原因，先講再等。
2. **repo 是 Private** → 免費帳號不行，改成 Public（見上面 Lab 0）。
3. **網址少了結尾的斜線** → `.../my-life-tools` 要寫成 `.../my-life-tools/`
4. **帳號大小寫打錯** → GitHub 帳號在網址裡不分大小寫，但 repo 名稱**分**。
5. **根目錄沒有 `index.html`** → 直接開 `https://<帳號>.github.io/my-life-tools/habits/`

### 「Settings 裡面找不到 Pages」

在**左側**選單，要往下捲，在「Code and automation」那一區。
不是上面的分頁列。學員很常在上排找。

### 「頁面出來了但沒有樣式 / 圖片是破的」

路徑寫成絕對路徑了。

```text
這個頁面放到 GitHub Pages 上樣式跑掉了，請把所有路徑改成相對路徑
```

## 任何時候

### 「修改後原本可用的功能無法運作」

```text
請把剛剛的改動還原，回到上一個能正常運作的版本
```

還是不行的話，走 GitHub 網頁：repo → **Commits** → 找到還能動的那一版 →
右邊 **<>** 看當時的檔案 → 複製內容貼回來。

可補充說明：「這就是一開始把內容放上 GitHub 的原因。」
並指出版本紀錄可以協助回到先前可用的狀態。

### 「我落後兩個 Lab 了」

不要讓他從頭追。跳到**當前** Lab，前面的成果課後再補。

隨堂網站上每個 Lab 都有「需要追上進度？」區塊，內含可以直接使用的提示詞。
指出位置後繼續查看全班狀況；同一位學員的個別處理原則上不超過 3 分鐘，
優先處理會影響多人進度的問題，並定期查看其他學員的畫面。

### 網路中斷

Claude Code 完全依賴網路，沒有離線模式。

- 開手機熱點給最需要的幾個人
- 全場性斷網 → 改由講師示範，並提供隨堂網站網址供學員課後操作
- 這就是為什麼隨堂網站是**單一檔案、不連外**：斷網時已經載入的頁面仍然可用
