## GitHub Actions 是什麼

<br>

### 想像 GitHub 免費借你一台電腦，放在雲端

你寫一張紙條給它：

---

## 那張紙條就叫 workflow

<br>

```
my-life-tools/
└── .github/
    └── workflows/
        └── digest.yml   ← 這張紙條
```

<br>

> 上面寫：**幾點做**、**做什麼**

---

## 步驟 1：寫下那張紙條

```text
我要一個每天自動執行的功能，請用 GitHub Actions 做：
1. 每天台灣時間早上 6 點自動執行
2. 抓 Google 新聞的 RSS（繁體中文台灣版），取前 5 則標題和連結
3. 存成 digest/YYYY-MM-DD.md 這樣的檔案，然後自動 commit 回這個 repo

要求：
- 一定要能手動按按鈕執行（workflow_dispatch），我今天上課就要看到結果
- workflow 要有 contents: write 權限，不然推不回來
- 不要用任何 npm 套件，用 Node 內建的功能就好

做好之後把檔案 push 上去。
```

## 紅色的處理流程

<br>

1. 點那一列**紅色**的紀錄
2. 點左邊紅色 ✗ 的那個步驟
3. **把錯誤訊息整段複製**
4. 貼回 Claude Code：

```text
我的 GitHub Actions 失敗了，錯誤訊息是：
（貼上）
請修好它，然後 push 上去。
```

5. 回 Actions 再按一次 **Run workflow**

---

## 最常見的兩種紅字

<br>

| 訊息裡有 | 貼這句 |
| --- | --- |
| `permission` `403` | `workflow 推不回 repo，請加上 permissions: contents: write` |
| `fetch failed` | `抓資料失敗了，請加上錯誤處理，抓不到的時候也要正常結束` |

## 步驟 1：習慣追蹤表

```text
在 habits/ 資料夾做一個習慣追蹤表，單一個 index.html：
1. 我可以自己新增想追蹤的習慣（例如喝水、運動、閱讀）
2. 顯示最近 30 天的格子，點一下代表那天有做到，變成綠色
3. 每個習慣顯示「連續達成幾天」
4. 資料存在瀏覽器裡，關掉再打開還在
中文介面，手機上要能用。做好幫我打開來看。
```

<br>

> 一樣：不滿意就繼續改

---

## 步驟 2：做一個首頁

```text
在 repo 根目錄做一個 index.html 當首頁，
用卡片的方式連到我做的工具：
- expenses/ 記帳小工具
- habits/ 習慣追蹤表
- digest/ 每日摘要
風格要跟那兩個工具一致，中文介面，手機上要好看。
最上面放一個標題「我的生活小工具」。
```

## 在 GitHub 網頁上做（不用 Claude Code）

<br>

## 三、責任不會轉移

<br>

它做錯了，壞掉的是

**你的**東西、**你的**資料、**你的**信譽。

<br>

### 你沒辦法說「是 AI 弄的」

像一人公司的 CEO：可以充分授權，

## 四、你會有一種錯覺

<br>

### 「我好像什麼都會了」

<br>

不需要假裝成別的東西。
