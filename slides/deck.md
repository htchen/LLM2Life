<br>

### 一個**看得到你電腦裡的檔案**、

## 你可能用過的 AI 是這樣

<br>

```
你：幫我寫一個記帳程式

```

## Claude Code 是這樣

<br>

```

    做好了，你看看
```

<br>

**差別在於：它可以直接修改專案檔案。**

## Lab 1 和 Lab 2 的差別

---

## GitHub Actions 是什麼

<br>

### GitHub 依照 workflow 在雲端執行指定工作

<br>

你寫一張紙條給它：

> 「每天早上 6 點，幫我做這件事。」

<br>

**工作會在 GitHub 雲端執行，個人筆電不需保持開機。**

---

## 那張紙條就叫 workflow

<br>

```
my-life-tools/
└── .github/
    └── workflows/
        └── digest.yml   ← 這張紙條
```

<br>

> 上面寫：**幾點做**、**做什麼**

---

## 步驟 1：寫下那張紙條

```text
我要一個每天自動執行的功能，請用 GitHub Actions 做：
1. 每天台灣時間早上 6 點自動執行
2. 抓 Google 新聞的 RSS（繁體中文台灣版），取前 5 則標題和連結
3. 存成 digest/YYYY-MM-DD.md 這樣的檔案，然後自動 commit 回這個 repo

要求：
- 一定要能手動按按鈕執行（workflow_dispatch），我今天上課就要看到結果
- workflow 要有 contents: write 權限，不然推不回來
- 不要用任何 npm 套件，用 Node 內建的功能就好

做好之後把檔案 push 上去。
```

---

## 為什麼要寫出這些限制？

<br>

### 後面那三個「要求」，
### 是這個題目**三個最常見的問題**

<br>

> 先說明，可以減少常見錯誤。

<br>

**這就是清楚描述需求的實際做法：**
**重點是把已知限制寫出來。**

## 紅色的處理流程

<br>

1. 點那一列**紅色**的紀錄
2. 點左邊紅色 ✗ 的那個步驟
3. **把錯誤訊息整段複製**
4. 貼回 Claude Code：

```text
我的 GitHub Actions 失敗了，錯誤訊息是：
（貼上）
請修好它，然後 push 上去。
```

5. 回 Actions 再按一次 **Run workflow**

---

## 最常見的兩種紅字

<br>

| 訊息裡有 | 貼這句 |
| --- | --- |
| `permission` `403` | `workflow 推不回 repo，請加上 permissions: contents: write` |
| `fetch failed` | `抓資料失敗了，請加上錯誤處理，抓不到的時候也要正常結束` |
