給種子教師

把這場工作坊
帶回自己的學校

本頁提供給返校後自行辦理三小時啟動場的教師。它不是一門課——沒有東西要教會； 是讓同事一起跨過第一次：帳號、第一個檔案、第一個公開網址、第一次改壞再退回。 每個人帶著已上線的第一版離開，之後各自迭代。

預設辦的是免費版：參加的教師僅需免費帳號，無須訂閱或安裝。

教材可自由改編· 不需事先告知· 學生不需要任何帳號

無須自行重寫。四個介面連同講師文件均已完備。

二、辦理前要先決定的三件事

  1. 時間完整版 195 分鐘。場地只有 180 分鐘時，依 timeline.md「180 分鐘場地的調整」逐項縮，不要臨場自己抓。
  2. 人數建議 12–20 人。超過 20 人時，發想與實作階段需要第二位協助巡場，否則卡住的人要等太久。
  3. 網路全程需要連 claude.ai 與 github.com。場地若有網路白名單，務必在課前確認這兩個網域可通——這是最常見、也最無法臨場補救的問題。

三、辦理前一定要做的兩件事

寄課前通知信

用 pre-workshop-email.md，把日期、時間、地點與聯絡信箱填進去，信裡附上 課前準備頁的連結。沒有寄信，課程前段就得用來處理帳號與登入問題。

自己先走一次共同練習

至少完整做出「探究提問卡」一次，以掌握生成內容的實際樣貌與學員可能卡住之處， 效果優於反覆閱讀講稿。

四、當天最容易出問題的三件事

  1. 登入 claude.ai 之後點到 Code 分頁那是付費功能。免費版只用中間的一般聊天視窗。
  2. AI 回覆的程式碼被「⋯」省略學員會存出一個壞掉的檔案。這就是每個提示詞結尾都要寫「請給我完整程式碼」的原因。
  3. repo 建成 Private免費帳號要用 GitHub Pages 就必須是 Public，建立時就要選對，中途才改會多花五分鐘。

其餘狀況查 疑難排解。

五、可以改什麼，不建議改什麼

放心改

共同練習的題目（現為探究提問卡，可更換為任一學科）、備用題目、範例、配色、 投影片用語、段落長度——總長對得起來即可。

以下六個檢查點是課程能不能收尾的關鍵。拿掉任何一個， 學員多半會做出一個看起來很忙、但無法驗收的東西。

  1. 先列三個問題，再選一個直接決定題目的人，通常選到自己講不清楚的那一個。
  2. 必要功能不超過三項，且至少兩項「這次不做」寫不出「不做」，代表題目還太大。
  3. 每一個實作步驟都有可操作的驗收方式「做完了」不是驗收，「輸入 X 會看到 Y」才是。
  4. 第一輪先做出可用的核心流程，並且先保存不是先做空白框架，也不是做到一半才存。
  5. 最後一段停止新增功能改為展示與規劃下一版。時間到就停，未完成的列入下一版。
  6. 先讓學員自己寫出判斷，再請 AI 協助順序顛倒的話，學員會拿到一個自己無法評估的答案。

不要改

任何需要學生自行註冊帳號的步驟。原因見下一節。

六、AI 工具可以換，GitHub 那一段不能省

這套流程不綁定 Claude。返校後若所處環境為 Google Workspace、同事僅有 Gemini， 直接以其執行同一套流程完全成立——建議明講，不必迴避此問題。

可以換掉的部分

產生第一版。Claude、Gemini、ChatGPT 都做得到， Canvas 這類介面還有即時預覽，甚至比免費版的「複製 → 貼上 → 存檔 → 打開」更快。 我們用手動流程是為了在禁止安裝軟體的電腦教室也能跑，那是代價，不是優點。

不能省掉的部分

把成果存回 GitHub。網址、回溯、所有權、交付——這四件事廠商託管的 canvas 目前都給不了。省掉這一步，老師做出來的東西會留在某個產品裡， 換工具就沒了，也交不到同事手上。

換工具時，以下三件事必須保留，其餘都可以調整：

  1. 先把問題寫成可驗收的規格不依賴任何工具，也是整套流程最難的一步。
  2. 把能運作的版本存回 GitHub這是唯一不能換掉的一段。
  3. 依自己寫的驗收條件迭代不是看 AI 說「完成了」。

一條誠實的界線

只要做一次性、用完就丟的東西——今天下午要一個搶答遊戲—— 開 Canvas 五分鐘做完最合理，GitHub 是多餘的。這門課的對象是 想累積、想改進、想交給同事的老師。把這條界線講清楚， 比宣稱哪個工具比較好更有說服力。

七、學生那一層：他們不需要任何帳號

這是課程刻意的設計。工具由教師製作，學生僅需開啟網頁使用。 學生本人不需要註冊 claude.ai，也不需要 GitHub 帳號，因此不會遇到未成年帳號與家長同意的問題。

  • 專題發布於 https://你的帳號.github.io/my-life-tools/project/，將網址或 QR code 提供給學生
  • 或直接投影出來，全班共用一份
  • 學生填寫的內容留存於其自身的瀏覽器，不會傳送至任何位置，教師端亦不會收到

想收集學生填寫的結果？

那已經超出課堂版本的技術範圍（需要後端與個資處理）。請列入下一版， 不要在三小時的場次裡嘗試。

八、收束時要說的話

參加的老師最後帶走的不是一個工具，而是一套可以重複使用的流程。 完整說法在 insights.md 的「補充段落」，最短的版本是：

能自主驗證的事，會愈來愈快；不能自主驗證的事，仍然靠人。
課程中的六個步驟，與學生的科學探究歷程為同一套結構。

九、辦完之後：回傳一張截圖

啟動場的意思是之後會繼續。讓它繼續的最小動作，是把同事做出來的東西回傳一張圖。

到 github.com/htchen/LLM2Life/issues/new 開一則 issue（用參加時的 GitHub 帳號即可），附上：

  • 一張截圖：任何一位同事做出來的工具，實際執行的畫面
  • 公開網址（若已發布）
  • 科目與大致的題目；學校可寫可不寫

它會放上案例頁——下一批老師看到的實績，就是你這一場。

發布前會去識別化。截圖中若有姓名（螢幕分享的與會者標示、學生名單）會裁掉； 不放任何學生個資。你也可以先裁好再傳。
