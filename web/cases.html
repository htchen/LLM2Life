案例一：一門課的一整個學期教材

2026 年春季，一門大學程式設計課（Python、Flask、地圖 API）的 16 週講義、實驗與小考，全程以 Claude Code 製作並保存於版本庫。

114commit 總數
56由 Claude 直接署名（49%）
38經 Pull Request 合併
16週教材，195 個檔案

期間為 1 月 5 日至 6 月 1 日。作者欄位寫著 Claude 的 commit 附有 Claude Code 的工作階段連結，點進去看得到每一次改了什麼、為什麼改。 這不是宣稱，是可以打開來核對的紀錄。

這個案例證明什麼，不證明什麼。 授課者具備程式背景，課程本身也是程式設計課， 因此它不能用來主張「沒有程式背景也做得到」。 它證明的是另一件事：這套流程撐得起一整個學期的真實教材， 且每一次改動都可稽核、可回溯、可移轉——也就是課程所說的 「差異在產出之後的處置」，在一個學期的尺度上實際成立。

github.com/htchen/I2P_Python 公開版本庫。建議直接看 commit 歷史與已合併的 Pull Request。

案例二：學生的期末專題

同一門課的期末專題。學生以相同流程完成一個地圖任務網頁： 在真實街道圖上接受外送任務、規劃路線，並與兩個 AI 對手競賽計分。

畫面待補。此處將放入課堂實際執行的截圖。

此案例的價值與案例一不同：產出者是學習者，不是授課者。 它回答的是在座教師最想問的一句話——學生自己做得出來嗎。

為什麼把案例單獨列出來

六十分鐘的演講放得下兩段現場示範，放不下完整的佐證。 示範證明的是「當場做得出來」，案例證明的是「撐得過一整個學期」——後者才是決定 是否投入時間的依據。

回到專案首頁課程總覽、教材與各項連結。 種子教師指南回校自行開課時，從這裡開始。 四個互動範例課堂上可直接打開的成品，各附 QR code。
