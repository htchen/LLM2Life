# 洞見段落：講稿與論證（免費版，講師用）

這份檔案的論證與付費版不同。付費版強調轉成可執行形式的成本降低；
本版本則讓學員手動完成建立檔案的步驟。講師若同時教授兩個版本，
應在課前確認各版本的主張與操作差異。

三個微段落各 3 分鐘，放在對應的 Lab 之後；最後一個 12 分鐘的收束論證。
編排原則跟付費版相同：**先體驗，再命名**。每個洞見都只講學員十分鐘前剛親身
經歷過的事。若將抽象說明移到操作之前，學員缺少實例可以對照，理解效果會降低。

---

## 洞見 1 — 一件事會被自動化，一件事不會

**位置：** Lab 1 之後，休息之前 · **3 分鐘**

### 他們剛經歷了什麼

第一版可能不完全符合需求。學員回到聊天視窗補充條件，再複製新版本、覆蓋舊內容、
存檔並重新整理。這個流程可以分成可重複的操作與需要判斷的工作。

### 怎麼講

> 剛剛你做了兩三次「複製、貼上、存檔」。這個動作，感覺起來很機械對不對？
>
> 複製、貼上與存檔是可重複的操作，可以由工具自動處理；Claude Code 即可直接執行這些步驟。
>
> 另一部分需要判斷：**決定要加什麼功能、確認介面是否符合需求、判斷版本是否可用。**
>
> 需求、決策與驗證仍由使用者負責。

**收在這一句上，然後停頓：**

> **今天你把兩件事都做了一遍。**
> **請區分工具可以自動處理的步驟，以及使用者仍需負責的判斷。**

### 為什麼這是真的（Q&A 用）

這是軟體開發中的實際分工：可重複的轉換操作
（把決定好的內容建立成可執行格式）可以自動化，而判斷
「要做什麼」「做得對不對」需要對脈絡的理解，這正是自動化工具目前仍然
依賴使用者確認。學員手動完成一次前半段後，可以直接理解兩類工作的差異。

### 會被挑戰的點

- **「所以複製貼上沒有價值？」**
  親手完成一次有助於理解自動化工具省略的步驟與需要驗證的結果。
- **「這些步驟未來會被自動化，今天還需要練習嗎？」**
  課堂同時練習需求描述與結果驗證；即使建立檔案的步驟自動化，這兩項工作仍然需要。

## 洞見 2 — 付費工具在省的是哪一段

**位置：** Lab 2 之後 · **3 分鐘**

### 他們剛經歷了什麼

學員以複製貼上方式把兩個檔案放上 GitHub，按下按鈕後 workflow 成功執行。
這段說明自動化是否能執行，與檔案由何種工具建立是兩件不同的事。

### 怎麼講

> 剛剛那個東西，你是用滑鼠複製貼上放上去的。
>
> GitHub Actions 只依照 repo 中的檔案執行，不判斷檔案是手動貼上或由工具寫入。
>
> 因此，使用免費聊天介面與 GitHub 網頁也可以建立排程自動化。

**收束：**

> 那付費的工具（例如 Claude Code）到底在幫你省什麼？
>
> **不是「讓自動化變得可能」——那件事本來就可能，你剛剛才做到。**
>
> 它省的是**前面那幾步**：問完之後，複製、貼上、存檔、確認格式對不對，
> 這些今天花了你不少時間的動作。
>
> 今天手動完成這些步驟後，可以具體理解付費工具省略的操作範圍。

### 為什麼這是真的

GitHub Actions 依 repo 中的 workflow 執行，不記錄該檔案由何種工具產生。
付費版所降低的是產生、修改與保存正確檔案的部分成本，而不是 GitHub Actions 的執行機制。

### 會被挑戰的點

- **「什麼情況適合改用付費工具？」**
  依操作頻率與時間成本判斷。偶爾處理時可使用今天的方法；頻繁重複時，可評估自動化建立檔案的步驟。
- **「這段是在推薦付費工具嗎？」**
  不是。這段只比較操作範圍與時間成本，讓學員自行判斷是否需要。

## 洞見 3 — 看過內容不等於已完成驗證

**位置：** Lab 3 之後 · **3 分鐘**

### 他們剛經歷了什麼

紅色的 ✗、404、以及今天每一段結尾的 ✅ 檢查點——這些跟付費版一樣。
本版本另外包含手動複製與貼上程式碼的步驟。

### 怎麼講

> 今天每一段程式碼都由你從 Claude 回覆複製到檔案中。
>
> 這讓你有機會查看實際內容，但不表示需要逐行理解，也不表示程式碼已經正確。

**給一個帶得走的判準：**

> 但看過一遍，不等於看懂、也不等於它是對的。
>
> 明顯不符合需求的結果容易發現；更需要注意的是外觀看似正確、實際行為卻不正確的結果。
>
> 所以新的識字能力不是讀懂程式碼，是：**在你按下 Enter 或 Commit 之前，
> 先想好「做好了應該長什麼樣」。**

（呼應他們今天每一次的「先本機測試，滿意才推上 GitHub」的節奏。）

### 為什麼這是真的

自動化偏誤（automation bias）會讓使用者因系統多數時候正確而降低查核頻率。
手動流程讓學員接觸到實際內容，但有效驗證仍需依靠預先定義的結果與實際操作。
即使改用自動化工具，也應保留修改前查看範圍、修改後實際測試的習慣。

### 會被挑戰的點

- **「我看了也看不懂程式碼在寫什麼，這樣算有看嗎？」**
  算。你不需要看懂語法，你需要看的是**行為**：輸入這個，應該出現那個。
  這是你今天一直在做的檢查點練習，不是新技能。

## 收束論證（12 分鐘）

**位置：** 洞見 3 之後、成果分享之後

以與付費版相同的三項工作框架開場，但中段需說明本版本仍由學員手動建立檔案。

### 一、今天真正發生的事（1 分鐘）

> 這堂課不是程式設計入門，也不以學會程式語法為目標。
>
> 你們完成了三個可使用的工具，其中一個已發布成公開網站，
> 並且全程使用免費帳號與瀏覽器操作。
>
> 同時也練習了需求描述、建立檔案與結果驗證。

### 二、哪些工作仍由學員手動完成（4 分鐘）

> 做出一個軟體，一直都需要三件事：
>
> **一、知道要什麼。**
> **二、把它翻譯成機器聽得懂的話。**
> **三、確認它真的對。**
>
> 使用 Claude Code 時，工具可以直接處理第二件事的大部分初步工作。
>
> **本版本仍由學員手動完成複製、貼上與存檔。**

**停頓，然後：**

> 這是本版本與付費版的主要操作差異。
>
> 手動流程可以拆成固定步驟：提出需求、取得內容、複製、貼上、存檔、確認。
>
> 自動化工具會直接處理其中數個步驟；今天的操作讓你看過這些步驟與檔案之間的關係。

這是整場的核心。請放慢速度並對照 Lab 1 與 Lab 2 的操作。

### 三、所以那些工具在做什麼（3 分鐘）

> 那些自動幫你做這件事的工具（例如 Claude Code），做的事情
> **跟你們今天做的事一模一樣**——問、產生程式碼、變成檔案、存進 repo。
>
> 差別只在於：**它們把「複製、貼上、存檔」這幾步自動化掉了。**
>
> 值不值得換一個工具，答案很簡單：
>
> 如果需要頻繁重複，可以評估改用自動化工具；
> 如果只是偶爾處理，今天的方法即可完成工作。

### 四、使用限制（3 分鐘）— **必須保留**

> 使用本流程時，需要注意三件事：
>
> **一、AI 的語氣可能很確定，但輸出仍可能有錯。** 看起來正確不等於已通過驗證。
>
> **二、責任不會轉移。** 它給的東西有問題，出問題的是你的帳號、你的資料。
> 仍需由使用者確認內容與影響。
>
> **三、手動流程需要額外時間。** 如果需要頻繁重複，可評估改用自動化工具。

### 五、後續練習重點（1 分鐘）

> 兩件事：
>
> **練「說清楚」**——包括記得每次都要求「請給我完整程式碼」。
>
> **練「驗證」**——動手之前先想「做好了應該長什麼樣」。
>
> 請從自己熟悉的工作內容開始，因為你最了解其中的需求與判斷標準。

### 六、收束（30 秒）

> 回家作業第三題是「做一個只有你需要的小工具」。
>
> 如果這項流程需要頻繁重複，可評估使用能直接建立與修改檔案的工具。
> 今天的操作已經說明這些工具省略的步驟。

## Q&A 常見問題

| 問題 | 怎麼回 |
| --- | --- |
| 「這是在推薦付費版嗎？」 | 不是。本課程說明兩種版本的操作差異與時間成本，由學員依使用頻率自行判斷。 |
| 「免費版是不是比較差？」 | 結果可以相同，但免費版需要手動建立與更新檔案，因此操作時間較長。 |
| 「我還需要學程式嗎？」 | 看你想做什麼。今天學的「說清楚＋驗證」在任何工具上都用得到；
「複製貼上存檔」這套機械動作，換了更快的工具就不需要了。 |
| 「為什麼付費版可以自動存檔，我不行？」 | 那類工具取得使用者同意後可以操作檔案系統；一般聊天介面只有文字回覆，沒有相同權限。 |
