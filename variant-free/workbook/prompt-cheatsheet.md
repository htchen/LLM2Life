# 帶回家的重點整理（免費版）

可以印出或加入書籤，供課後查閱。

---

## 一、描述需求的格式

如果結果不符合預期，常見原因是條件不足。請補上以下四項資訊：

> **我要做什麼** + **有哪些功能** + **我要看到什麼** + **有什麼限制**

而且**免費版一定要多加一句**：

> **「請給我完整、可以直接存成檔案使用的程式碼，不要省略任何部分。」**

❌ `做一個待辦清單`

✅ ```
做一個待辦清單網頁，單一個 index.html：
可以新增、打勾完成、刪除，資料存在瀏覽器裡。
中文介面，手機上能用。
請給我完整、可以直接存成檔案使用的程式碼，不要省略。
```

## 二、四步驟：把文字變成檔案

這是今天重複最多次的動作：

```
複製 Claude 給的文字  →  貼到記事本／文字編輯  →  存成正確檔名  →  雙擊打開
```

**改東西的時候：**

```
複製新的完整版本  →  全選舊內容蓋掉  →  存檔  →  重新整理瀏覽器
```

**Mac 使用者在貼上前先按 `Shift + Cmd + T`（製作純文字）**，
避免儲存成 RTF 格式。

## 四、應該記住的三句話

> ### 有些步驟可以自動化，有些責任仍由使用者承擔
>
> 今天的複製、貼上與存檔動作，可以由工具自動處理。
> 這正是 Claude Code 這類工具在做的事。但**決定要做什麼、判斷做出來的對不對**，
> 需求、決策與結果驗證仍由使用者負責。手動完成一次流程後，
> 更容易理解自動化工具處理的範圍。

> ### 看起來對 ≠ 對
>
> 明顯不符合需求的結果容易發現；更需要注意的是外觀看似正確、實際行為卻不正確的結果。
> 今天的手動複製貼上流程讓你接觸到實際內容。
> 但查看內容不等於驗證，仍需以畫面與實際操作確認結果。

> ### 越難收回的事，越要親眼看過再放行
>
> 本機測試檔案可以在保留備份的前提下嘗試。貼到 GitHub 並按下 Commit 前，
> 先確認內容與影響範圍。

## 五、GitHub 名詞對照

| 你看到的 | 白話 |

| repository / repo | 一個會記得所有版本的資料夾 |

| Actions | GitHub 的雲端執行環境，可以依時間執行工作 |
| workflow | 定義執行時間與工作步驟的檔案 |
| Pages | 把你的網頁變成一個公開網址 |

## 六、回家繼續的三個題目

由易到難，做完一個再做下一個：

1. **改你今天做的東西。** 把記帳工具改成你真的會用的樣子。
2. **改每日摘要。** 換成你真正想每天收到的：你追的網站、天氣、匯率。
3. **做一個只有你需要的工具。** 想一項每週重複的手動工作，
   描述給 Claude，讓它幫你想解法。

Claude Code 這類工具可以自動處理今天手動完成的複製、貼上與存檔步驟。
理解各步驟後，可以依需求決定是否改用自動化工具。
