開始之前

兩分鐘認識今天的動作。這個版本跟「用 Claude Code」的版本只差一件事。

🆓 免費版的操作方式

Claude Code 可以直接把程式碼寫成檔案並開啟瀏覽器；本版本使用一般聊天介面， 因此需要自行把 AI 回覆建立成檔案。這項操作會先練習一次，後續專題重複使用。

四個步驟，今天會重複很多次：

問→複製→存檔→打開

⚠️ 登入 claude.ai 後，請不要點 Code 分頁

畫面上方如果看到一個 Code 分頁，那是需要付費的功能。 我們今天只用中間可以打字的一般聊天視窗，跟平常跟 AI 聊天一樣。

⚠️ 兩個常見存檔問題

GitHub Actions 可以依照 workflow，在雲端執行指定工作。

檔案無論由滑鼠複製貼上或工具寫入，GitHub 都會以相同方式處理。

遇到問題

依畫面症狀查找。本版本另外包含檔案格式與副檔名問題。

先保留完整錯誤訊息

看到錯誤訊息或畫面不正確時， 完整複製相關訊息，貼回聊天視窗，並要求修改後的完整版本。

你看到的怎麼辦
雙擊打開的是記事本，不是瀏覽器存成了 .html.txt。存檔類型要選「所有檔案」
Mac 開啟後顯示程式碼或格式不正確確認已使用「製作純文字」，重新開檔案先按 Shift+Cmd+T
畫面一片空白按 F12 複製紅色錯誤 →「畫面是空白的，主控台出現這個錯誤：（貼上）」
重新整理資料就不見了某些瀏覽器對雙擊打開的檔案會限制儲存功能，換 Chrome 或 Edge 試試
它的回答中間寫「...」被截斷「請重新給我完整版本，不要省略任何一行」
修改後原本可用的功能無法運作回聊天視窗要求「一開始可正常運作的完整版本」
結果跟需求不一致補上：功能 + 預期結果 + 請給我完整程式碼
需要追上課程進度先保留目前可操作版本，未完成內容移到「下一版」

① 有些步驟可以自動化，有些責任仍由使用者承擔

今天完成了兩類工作：可重複的操作（複製、貼上、存檔）和 需要判斷的工作（選擇功能、確認結果）。

工具可以處理部分重複操作；需求、決策與結果驗證仍由使用者負責。

② 計畫可以依實作結果更新

看到第一版後發現新的限制，可以先更新目標與步驟，再進行下一輪。

免費版的檔案操作較多，但範圍取捨與驗收原則相同。

③ 每一步都需要可操作的驗收方式

手動複製貼上讓學員看到實際程式碼，但不要求逐行理解。

查看內容不代表結果正確。需要注意外觀看似正確、實際行為卻不正確的情況， 帶走這條判準：越難收回的事，越要親眼看過再放行。

使用限制

  • AI 的語氣可能很確定，輸出仍可能有錯。 看起來正確不等於已通過驗證。
  • 責任不會轉移。 出問題的是你的帳號、你的資料。
  • 手動流程需要額外時間。 如果需要頻繁重複，可評估改用自動化工具。

後續練習重點

練「說清楚」——包括要求「請給我完整程式碼」。

練「驗證」——動手之前先想「做好了應該長什麼樣」。 請從自己熟悉的工作內容開始，因為你最了解其中的需求與判斷標準。

操作原則

  • 每次都要求「請給我完整程式碼」
  • 需要調整時直接補充需求，全選蓋掉、存檔、重新整理
  • 看到紅字或畫面不對 → 整段複製 → 貼回去
  • Mac 貼上前先按 Shift+Cmd+T
  • 越難收回的事，越要親眼看過再放行

GitHub 名詞對照

  • repo — 會記得所有版本的資料夾
  • Add file → Create new file — 在網頁上新增檔案
  • Commit changes — 存檔並留下紀錄
  • Actions — GitHub 的雲端執行環境
  • Pages — 把網頁變成公開網址

下一版

  1. 重新執行今天的驗收條件，記錄未通過項目
  2. 從「這次不做」選一項，加入下一版計畫
  3. 完成一個步驟、測試並保存完整版本
