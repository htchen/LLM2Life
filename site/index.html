開始之前

兩分鐘確認。這一段沒過，後面都動不了。

⚠️ Claude Code 需要付費方案

需要 Pro、Max、Team 或 Enterprise 方案，免費的 Claude 帳號無法使用，這一點沒有例外。

怎麼確認：打開 Claude 桌面版 → 點最上面中間的 Code 分頁。看到可以打字的畫面就沒問題；跳出要你升級 → 請現在舉手，講師會安排你跟同學兩人一組。不要自己卡在這裡。

✅ 開始之前

裝不起來？用瀏覽器版，完全不用安裝

打開 claude.ai/code，登入後照畫面指示連結 GitHub 帳號即可。一樣需要付費方案。

這條路線的差別：檔案在雲端，不在你的電腦裡。改完之後要按 Create PR 才會存回主要版本。走這條路線的話，請先跳到 Lab 3 的步驟 4 把網站開起來，這樣接下來每一段你都看得到成果。

Lab 1 · 記帳小工具35 分鐘

記帳只是題目。這一段真正要學的是怎麼把想法講成它聽得懂的話。

講話的公式

我要做什麼+有哪些功能+我要看到什麼+有什麼限制

想像你在交代一個很能幹、但沒讀過你腦袋的人。他不知道你要中文介面、不知道你要放手機看——除非你講。

步驟 1做出第一版
貼給 Claude Code
在 expenses/ 資料夾做一個記帳小工具，單一個 index.html 檔案就好，不要用任何套件。
功能：
1. 可以輸入金額、項目名稱，按一下就新增一筆
2. 下面列出所有紀錄，每一筆可以刪掉
3. 最上面顯示這個月的總花費
4. 資料存在瀏覽器裡，關掉再打開還在
畫面請做得乾淨好看，中文介面，手機上也要能用。
做好之後幫我在瀏覽器打開來看。

它跑很久是正常的，它在讀檔案、寫檔案、檢查自己。可以停、可以插話、不用重來。趁這時候想：等一下要加什麼功能？

步驟 2改成你想要的樣子 ⭐

這一步比第一版更重要

不滿意就再講一次，不用重來。你不會把它弄壞——就算弄壞了，下一句「請還原剛剛的改動」就救回來了。這是今天最值得帶走的習慣，請一定要親手試一次。

例如加分類
幫我加上「分類」功能：新增的時候可以選餐飲、交通、購物、其他，
列表上用不同顏色的標籤顯示，最上面再加一個各分類的小計。

或換成你自己想要的：加圖表、改成暖色系、金額加千分位、匯出 CSV……都可以。

步驟 3存回 GitHub
貼給 Claude Code
把目前的改動 commit 並 push 到 GitHub，commit 訊息用中文描述我做了什麼。

Lab 2 · 每天自動幫你做事35 分鐘

Lab 1 的東西要你打開它才會動。這一段做的東西，你在睡覺的時候它自己會做事。

GitHub Actions 是什麼

想像 GitHub 免費借你一台電腦，放在雲端。你寫一張紙條給它：「每天早上 6 點，幫我做這件事。」

然後它就真的會做。你的筆電關機也沒關係——做事的不是你的電腦。這張紙條叫 workflow。

步驟 1寫下那張紙條
貼給 Claude Code
我要一個每天自動執行的功能，請用 GitHub Actions 做：
1. 每天台灣時間早上 6 點自動執行
2. 抓 Google 新聞的 RSS（繁體中文台灣版），取前 5 則標題和連結
3. 存成 digest/YYYY-MM-DD.md 這樣的檔案，然後自動 commit 回這個 repo

要求：
- 一定要能手動按按鈕執行（workflow_dispatch），我今天上課就要看到結果
- workflow 要有 contents: write 權限，不然推不回來
- 不要用任何 npm 套件，用 Node 內建的功能就好

做好之後把檔案 push 上去。

為什麼要寫得這麼囉唆？

後面那三個「要求」是這個題目最容易踩的三個坑。先講清楚就不會踩到。這就是「把想法講清楚」的實際樣子——不是講得漂亮，是把你知道的限制講出來。

步驟 2按下按鈕，看它跑

⚠️ 檔案一定要先 push 上 GitHub，這一步才有東西可看。存在自己電腦裡不算。

  1. 打開你的 repo → 點上面的 Actions 分頁
  2. 左邊點你的 workflow（大概叫 Daily Digest）
  3. 右邊按 Run workflow → 再按一次綠色的 Run workflow

你會看到：🟡 黃色轉圈圈 → 大約 30 秒 → ✅ 綠色打勾。

步驟 3看成果

回 repo 首頁按 F5，會多出一個 digest/今天日期.md，點進去是今天的新聞標題。

這份檔案不是你放進去的

是那台雲端電腦幫你放的。而且每天早上 6 點它都會再做一次。

Lab 3 · 習慣儀表板 + 上線35 分鐘

前兩個 Lab 的成果只有你看得到。這一段結束時，你會有一個能傳到家族群組裡的網址。

步驟 1習慣追蹤表
貼給 Claude Code
在 habits/ 資料夾做一個習慣追蹤表，單一個 index.html：
1. 我可以自己新增想追蹤的習慣（例如喝水、運動、閱讀）
2. 顯示最近 30 天的格子，點一下代表那天有做到，變成綠色
3. 每個習慣顯示「連續達成幾天」
4. 資料存在瀏覽器裡，關掉再打開還在
中文介面，手機上要能用。做好幫我打開來看。
步驟 2做一個首頁
貼給 Claude Code
在 repo 根目錄做一個 index.html 當首頁，用卡片的方式連到我做的工具：
- expenses/ 記帳小工具
- habits/ 習慣追蹤表
- digest/ 每日摘要
風格要跟那兩個工具一致，中文介面，手機上要好看。
最上面放一個標題「我的生活小工具」。
步驟 3全部存回去
貼給 Claude Code
把全部改動 commit 並 push 到 GitHub。

⚠️ 這一步一定要成功，下一步才有東西可以公開。到 GitHub 重新整理，確認看得到 habits/ 和根目錄的 index.html。

步驟 4讓全世界都打得開 ⭐

這一步在 GitHub 網頁上做，不用 Claude Code：

  1. 你的 repo → 上排 Settings
  2. 左邊選單往下捲，找到 Pages（在 “Code and automation” 那一區，不是上排的分頁）
  3. Source 選 Deploy from a branch
  4. Branch 選 main，右邊資料夾選 / (root)
  5. 按 Save

然後你會拿到網址：https://你的帳號.github.io/my-life-tools/

⚠️ 現在打開會是 404 — 這是正常的

第一次部署要等 1–10 分鐘。趁等待的時候，把網址傳給自己。

📱 然後用你的手機打開它

這一步不要省。在自己手機上打開自己做的網站，是這三小時最好的部分。

帶回家的小抄

三小時裡真正需要記住的東西，全部在這裡。

五句救命的話

請把剛剛的改動還原，回到上一個能正常運作的版本
（貼上錯誤訊息）請修好它
幫我在瀏覽器打開這個頁面
把目前的改動 commit 並 push 到 GitHub
用我聽得懂的方式解釋你剛剛做了什麼，不要用專有名詞

心態（比技巧重要）

  • 不滿意就再講一次，不用重來
  • 它問「可以嗎」是在保護你
  • 它跑很久是正常的
  • 講得囉唆比講得漂亮有用
  • 紅色的錯誤不是失敗，是下一句話的材料

GitHub 名詞對照

  • repo — 會記得所有版本的資料夾
  • commit — 存檔，並寫一句改了什麼
  • push — 把存檔上傳到 GitHub
  • Actions — 雲端電腦，可按時自動做事
  • Pages — 把網頁變成公開網址

回家作業（由易到難）

  1. 把記帳工具改成你真的會用的樣子——你要的分類、你喜歡的顏色
  2. 把每日摘要改成你真的想收到的：你追的網站、天氣、匯率
  3. 做一個只有你需要的小工具 ⭐ 這個最重要

第 3 題卡住的話，先問它：

不知道要做什麼的時候

有沒有辦法自動化？請用我聽得懂的方式給我幾個做法，先不要寫程式。
