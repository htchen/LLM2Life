# 構想備忘（未定案）

這份檔案只保存尚未納入正式教材的候選做法。正式時間與順序以 `timeline.md` 為準。

## 備用題目池

學員沒有題目或題目超出範圍時，可依問題類型提供方向，不直接指定完整功能。
對象是高中教師，備用方向一律限定為**教師自己使用、不涉及學生個資與成績**：

| 問題類型 | 備用方向 |
| --- | --- |
| 重複記錄 | 課堂觀察記錄表、學生提問記錄、實驗數據登記表 |
| 重複計算 | 分組人數、評分換算、進度或單位計算器 |
| 資訊分散 | 單元教材連結頁、器材清點表 |
| 固定判斷 | 評分規準檢查表、出題涵蓋範圍檢查 |
| 學生使用 | 探究提問卡的學科變體、自我檢核表 |
| 概念視覺化 | 互動示範：一個滑桿 → 一個即時重畫的圖（單位圓與正弦波、二次函數係數、理想氣體、化學平衡、動滑輪） |
| 視覺化證明 | 圖本身就是論證（正弦和角公式、畢氏定理、面積法）。難度較高，且構造必須由老師提供 |
| 定期處理 | GitHub Actions 摘要或提醒（進階） |

備用題目仍需通過相同條件：一個主要使用者、一個核心問題、一個可展示流程、低風險。

**「學生使用」那一類要特別說清楚：** 做出來的是學生打開就能用的網頁，
學生填寫的內容留在自己的瀏覽器裡。要收集學生填寫的結果就需要後端與個資處理，
不列入課堂版本。

## 可評估的後續改進

### 發想蒐集方式

- 使用便利貼或共享白板，依「記錄、計算、整理、判斷」分群。
- 投票只用來找共同問題，不用來選出「最好」的創意。
- 課後保存匿名題目，逐步建立下一場的備用案例庫。

### 同儕檢查

- 發想階段：同桌只能問情境與目前做法，不先建議功能。
- 規劃階段：同桌確認能否理解驗收條件。
- 展示階段：同桌依問題、成果、驗收、下一步提供一項回饋。

### GitHub 延伸

- 用 GitHub Issues 保存下一版功能清單。
- 用 branch 與 Pull Request 練習在合併前查看差異。
- 用 Actions 在 push 時執行自動檢查。

這些概念適合續集課程，不放入初次三小時工作坊。

## 其他受眾變體

**目前的正式對象是高中教師（種子教師）**，教學情境已經寫進正式教材，不再是變體。
若要開給其他對象，只替換問題情境，不改變
「問題 → 目標 → 計畫 → 實作 → 驗證 → 下一步」主線：

- 小型工作室：庫存提醒、報價試算、工作排程檢查。
- 研究人員：文獻欄位整理、訪談進度追蹤、資料格式檢查。
- 一般成人：個人清單、費用計算器、追蹤表（這是本教材改為教師場次之前的原始設定）。

## 種子教師模式的後續構想

- **同校再訓的縮短版：** 種子教師回校開課時，參加者多半已經彼此熟悉、
  也知道彼此的教學情境，發想階段可以再縮短。尚未驗證縮到多短仍有效。
- **跨校題目庫：** 累積各科的專題成果與驗收條件，讓下一場直接有同科範例可看。
- **第二次回訓：** 針對已經做出第一版的老師，處理「學生實際用過之後要怎麼改」，
  這是目前三小時場次碰不到、但真正決定工具會不會被繼續使用的一段。

## 不採用

- 不採用人物或名人類比。
- 不以功能數量或視覺效果比較學員成果。
- 不在發想階段要求 AI 直接產生完整解法。
- 不將登入、付款、敏感資料或多人同步納入初次課堂專題。
