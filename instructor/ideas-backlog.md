# 構想備忘（未定案）

這份檔案只保存尚未納入正式教材的候選做法。正式時間與順序以 `timeline.md` 為準。

## 備用題目池

學員沒有題目或題目超出範圍時，可依問題類型提供方向，不直接指定完整功能：

| 問題類型 | 備用方向 |
| --- | --- |
| 重複記錄 | 個人清單、簡易日誌、追蹤表 |
| 重複計算 | 費用、日期、進度或單位計算器 |
| 資訊分散 | 個人儀表板、資料整理頁 |
| 固定判斷 | 條件檢查表、選擇比較工具 |
| 定期處理 | GitHub Actions 摘要或提醒（進階） |

備用題目仍需通過相同條件：一個主要使用者、一個核心問題、一個可展示流程、低風險。

## 可評估的後續改進

### 發想蒐集方式

- 使用便利貼或共享白板，依「記錄、計算、整理、判斷」分群。
- 投票只用來找共同問題，不用來選出「最好」的創意。
- 課後保存匿名題目，逐步建立下一場的備用案例庫。

### 同儕檢查

- 發想階段：同桌只能問情境與目前做法，不先建議功能。
- 規劃階段：同桌確認能否理解驗收條件。
- 展示階段：同桌依問題、成果、驗收、下一步提供一項回饋。

### GitHub 延伸

- 用 GitHub Issues 保存下一版功能清單。
- 用 branch 與 Pull Request 練習在合併前查看差異。
- 用 Actions 在 push 時執行自動檢查。

這些概念適合續集課程，不放入初次三小時工作坊。

## 受眾變體

- 教師：課堂資料整理、教學活動計時、評量規則檢查。
- 小型工作室：庫存提醒、報價試算、工作排程檢查。
- 研究人員：文獻欄位整理、訪談進度追蹤、資料格式檢查。

變體只替換問題情境，不改變「問題 → 目標 → 計畫 → 實作 → 驗證 → 下一步」主線。

## 不採用

- 不採用人物或名人類比。
- 不以功能數量或視覺效果比較學員成果。
- 不在發想階段要求 AI 直接產生完整解法。
- 不將登入、付款、敏感資料或多人同步納入初次課堂專題。
