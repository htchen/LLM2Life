# 60 分鐘演講流程表（講者用）

**這份檔案是這場 60 分鐘演講的時間唯一真實來源。** 投影片：`slides/talk-60.md`（26 頁）。

## 這場的定位

對象是**種子教師**。這一小時**不安排學員動手**——60 分鐘內處理帳號與登入的風險太高，
而且那不是這場的目的。

| | 這場 60 分鐘 | 他們回去要開的 3 小時 |
| --- | --- | --- |
| 目標 | 決定要不要把三小時給同事 | 每個人做出一個可操作的最小版本 |
| 形式 | 演講 + 兩段現場示範 | 全程動手 |
| 學員需要 | 什麼都不用準備 | 兩個免費帳號，課前完成 |
| 教材 | `slides/talk-60.md` | `variant-free/`（195 分鐘） |

**兩者不是長短版的關係。** 三小時的教材不因為這場而縮減，它是這場的**交付物**。

## 講者事前準備

1. **自己先跑一次兩段示範。** 知道 AI 這次大概會回什麼、花多久。
2. **開好備援分頁**：`instructor/reference/sine-wave.html` 先在瀏覽器打開放著。
   現場產生失敗時直接切過去，**不要當場除錯**。
3. **準備一個乾淨的 repo**，示範二要當場 push 並打開網址。
4. **手機準備好**，示範二最後要用手機打開那個網址給大家看。
5. 白板寫上 `htchen.github.io/LLM2Life`，或做成 QR code。

## 兩段示範的重點

### 示範一（投影片 3–5，10 分鐘）

貼上提示詞、產生、打開。**不要解釋程式碼。**

做完之後的動作比產生本身重要：**把角度拉到 90°，指著 sin 顯示 1.000**，
說「我沒有在看它漂不漂亮，我在看它對不對」。這句話在投影片 19（驗收條件）會回來用。

**失敗處理：** 直接開備援分頁繼續。可以順帶說一句「第一版不完美是正常的，
三小時的版本裡有一整段在處理這件事」——這反而是真實素材。

### 示範二（投影片 8，約 4 分鐘）

存回 GitHub → 拿到網址 → **用手機打開**。

這一段一定要當場做完。沒有它，投影片 7 的三個好處只是宣稱。
手機打開那一刻是全場最有說服力的畫面：**學生不必登入、不必安裝，掃碼就能用。**

## 時間不夠時的取捨順序

依序捨棄，**不要臨場自己抓**：

1. 投影片 10（文明）與 13（context）——保留 11、12、14
2. 投影片 25（誠實的界線）
3. 投影片 20（構造來自老師）——**但對數學與物理老師的場次不要捨**

**任何情況都不要捨：** 投影片 5（驗收）、8（存回 GitHub）、14（主張）、
18（探究歷程對照）、22–24（帶走什麼）。
捨掉 8 或 18，這場就失去了與「已經在用 AI 聊天」的老師之間的差別。

## 最後一段要交代清楚的事

老師離場時必須知道三件事，投影片 22–24 就是為此存在：

1. **完整教材已經備好**，不必自己重寫
2. **CC BY 4.0**，可以改、可以發布、可以商用，只要標示出處
3. **回去怎麼開**：`htchen.github.io/LLM2Life/seed-teacher.html`

如果只能講一句話收尾，講這句：

> 今天看到的不是一個工具，是一套你可以再教一次的流程。

## 常見追問

現場最可能被問到的三個，完整回應方向在
[`insights.md`](insights.md)「補充段落」與「常見追問」：

| 追問 | 回應方向 |
| --- | --- |
| 我已經在用 Gemini Canvas 了，差別在哪？ | 產生第一版它很好用，有些還更快。差別在做完之後：網址、回溯、所有權、交付。 |
| 學生需要帳號嗎？ | 不需要。你做的是一個網頁，學生只是打開來用。 |
| 我不會寫程式，回去真的教得動嗎？ | 教材連講師文件、疑難排解與課前信都寫好了。你要做的判斷是題目適不適合，不是寫程式。 |
