# 種子教師指南：把這場工作坊帶回自己的學校

你在工作坊裡是學員；這份文件是給「回去之後要自己開一場」的你。

預設你要開的是**免費版**（`variant-free/`）：學員只要免費帳號，不必訂閱也不必安裝。
若你的場次由主辦方統一付費或參加者已有 Pro 以上方案，改用根目錄的付費版，流程相同。

教材以 [CC BY 4.0](../LICENSE) 授權，**可以刪改、可以換題目、可以自行發布，也可用於商業用途**，
唯一要求是標示出處。不需要事先告知我們。

## 二、開課前要先決定的三件事

**1. 時間。** 完整版 195 分鐘。場地只有 180 分鐘時，
依 `timeline.md`「180 分鐘場地的調整」逐項縮，不要臨場自己抓。

**2. 人數。** 建議 12–20 人。超過 20 人時，發想與實作階段需要第二位協助巡場，
否則卡住的人要等太久。

**3. 網路。** 全程需要連 claude.ai 與 github.com。
場地若有網路白名單，**務必在課前確認這兩個網域可通**——這是最常見、也最無法臨場補救的問題。

---

## 三、課前一定要做的兩件事

**寄課前通知信。** 用 `variant-free/instructor/pre-workshop-email.md`，
把日期、時間、地點與聯絡信箱填進去。信裡附上課前準備頁的連結。
沒有寄信，課程前段就得用來處理帳號與登入問題。

**自己先走一次共同練習。** 至少把「探究提問卡」做出來一次。
你會知道 AI 這次會回什麼、學員大概卡在哪，比讀十遍講稿有用。

---

## 四、當天最容易出問題的三件事

1. **登入 claude.ai 之後點到 Code 分頁** —— 那是付費功能。免費版只用中間的一般聊天視窗。
2. **AI 回覆的程式碼被「⋯」省略** —— 學員存出一個壞掉的檔案。
   這就是每個提示詞結尾都要寫「請給我完整程式碼」的原因。
3. **repo 建成 Private** —— 免費帳號要用 GitHub Pages 就必須是 Public，建立時就要選對。

其餘狀況查 `troubleshooting.md`。

## 五、可以改什麼，不建議改什麼

**放心改：**

- 共同練習的題目（現在是探究提問卡，換成你這一科的都可以）
- 備用題目、範例、配色、投影片用語
- 段落長度，只要總長對得起來

**改之前先想清楚：** 以下六個檢查點是課程能不能收尾的關鍵，
拿掉任何一個，學員多半會做出一個看起來很忙、但無法驗收的東西。

1. 學員先列三個問題，再選一個
2. 專題簡述的必要功能不超過三項，且至少列兩項「這次不做」
3. 每一個實作步驟都有可操作的驗收方式
4. 第一輪先做出可用的核心流程，並且先保存
5. 最後一段停止新增功能，改為展示與規劃下一版
6. 先讓學員自己寫出判斷，再請 AI 協助——順序不要顛倒

**不要改：** 任何需要學生自行註冊帳號的步驟。見下一節。

---

## 六、學生那一層：他們不需要任何帳號

這是本課程刻意的設計。**做出工具的是你，學生只是打開網頁使用它。**
學生本人不需要註冊 claude.ai，也不需要 GitHub 帳號，因此不會遇到未成年帳號與家長同意的問題。

把工具帶進課堂的做法：

- 你的專題發布在 `https://你的帳號.github.io/my-life-tools/project/`，把網址或 QR code 給學生
- 或直接投影出來，全班共用一份
- 學生填寫的內容存在**他們自己的瀏覽器裡**，不會傳到任何地方，也不會傳給你

如果你想收集學生填寫的結果，那已經超出課堂版本的技術範圍（需要後端與個資處理），
請列入下一版，不要在三小時的場次裡嘗試。

## 七、收束時要說的話

參加的老師最後帶走的不是一個工具，而是一套可以重複使用的流程。
`insights.md` 的「補充段落」裡有完整說法，最短的版本是：

> 能自主驗證的事，會愈來愈快；不能自主驗證的事，仍然靠人。
>
> 你今天走的六個步驟，和你要學生做的探究歷程是同一套。
