# 60 分鐘演講：四個示範的操作腳本

搭配 [`timeline.md`](timeline.md)（時間）與 [`script.md`](script.md)（講什麼）。
這一份只處理**手怎麼動**。

## 示範用 Claude Code CLI，在投影機上的終端機執行

**用你平常用的工具示範。** 講者示範一個自己從不使用的流程，比工具不匹配更傷；
而且第 31 頁那門課本來就是用 Claude Code 做的，示範用免費版反而對不上實績。

台下手上沒有 Claude Code 這件事，由第 29 頁一句話收掉——示範完指著它說：
「今天示範用的是付費工具；免費的對話介面能做到同一件事，三小時教材就是那個版本。不能省的是後半段。」

**終端機要讓台下看得到你打的字與它的每個動作**——那本身就是示範的一部分（第 9 頁三項工作的第二項正在發生）。
字級放大到後排看得到；不解釋終端機是什麼，它只是一個會回話的黑框。

remote-control（從手機驅動同一個工作階段）口頭提一句即可，不在台上用——多一層裝置與網路風險，且台下看不到提示詞。

## 最大的風險：GitHub Pages 第一次部署要等

**第一次啟用 Pages 會等 1–10 分鐘。** 如果你當場才建 repo、才開 Pages，
投影片 8 那個「用手機打開」極可能開出 404，而那是全場最關鍵的畫面。

### 前一天一定要做完

1. 建好示範用的 repo（Public），例如 `demo-live`
2. 放一個 `index.html`（隨便什麼內容都可以）
3. **Settings → Pages → Source 選 `Deploy from a branch`，branch 選 `main`**
4. 等到 `https://你的帳號.github.io/demo-live/` 真的打得開
5. 手機也開一次，確認手機網路能連

Pages 一旦「暖機」過，之後每次 commit 大約 30–60 秒就會更新。
**當天示範二上傳的是新檔案，走的是第二次以後的路徑，快得多。**

### 當天仍然可能沒這麼快

準備第二個分頁，先開好前一天已發布的版本。真的沒更新出來時直接說：

> 第一次部署要等幾分鐘，我昨天先放了一份在同一個位置，就是這個網址。

**把等待講出來，不要假裝即時。** 那本來就是 GitHub Pages 的真實行為，
學員回去自己做也會遇到，先講反而省得他們日後困惑。

## 開場前的畫面配置

投影前把這些都開好，**依序排在同一個瀏覽器視窗的分頁**，示範時左右切換即可：

| 分頁 | 內容 | 用於 |
| --- | --- | --- |
| 1 | 投影片（另一螢幕／簡報者檢視） | 全場 |
| 2 | 終端機：已在 `demo-live` 目錄內啟動 Claude Code | 示範一、二 |
| 3 | 你的 `demo-live` repo（GitHub 網頁） | 示範二時給台下看 commit |
| 4 | 前一天已發布的 Pages 網址 | 示範二備援 |
| 5 | `htchen.github.io/LLM2Life/examples/sine-addition.html` | 示範一備援 |
| 6 | `htchen.github.io/LLM2Life/examples/wordle-duel.html` | 示範三 |
| 7 | `htchen.github.io/LLM2Life/examples/lunyu-mentor.html` | 第 2 頁全場掃描；示範四 |

分頁 5、6、7 也可改開 repo 中 `shared/reference/` 的同名檔案，內容相同。
**使用網址的好處是不必事先 clone repo**，換一台電腦亦可開啟。

另外準備：

- **終端機**已 `cd` 進 `demo-live`、Claude Code 已登入並啟動；字級放大
- **提示詞先存成一個文字檔**，示範時從那裡複製貼進 Claude Code。不要對著投影片重打
- 瀏覽器**書籤列隱藏**、字級放大到後排看得到
- **手機**充好電，確認能連網

## 示範一：和角公式（投影片 3–5，8 分鐘）

### 步驟

| # | 動作 | 說什麼 |
| --- | --- | --- |
| 1 | 切到終端機（分頁 2） | 「我用的是我平常用的工具，等一下你們會看到它讀了什麼、寫了什麼」 |
| 2 | 從文字檔複製提示詞，貼進 Claude Code，送出 | 不要唸完整段，指出**中間三行是幾何構造** |
| 3 | 它讀、寫檔、開瀏覽器（約 1–2 分鐘） | 講投影片 4 的重點；並說「它現在做的就是第二項：轉成機器能執行的形式」 |
| 4 | 瀏覽器已打開；**拉動兩個滑桿**，指著下方三個數值 | 投影片 5 的關鍵句 |

若它沒有自己開瀏覽器，說「幫我在瀏覽器打開」即可。

### 步驟 3 的空檔要填滿

它跑的時候不要沉默。可以講：

- 這是高中數學的正弦和角公式，等一下會看到一個可以拉的證明
- 我剛才描述的不只是「我要看到什麼」，還包括「要怎麼畫」
- 那三行構造是我提供的，模型不會自己想出來——投影片 24 會回頭講這件事
- 它現在在螢幕上做的事，免費對話介面要你自己複製、存檔——三小時教材有那個版本

### 出錯時

| 狀況 | 處理 |
| --- | --- |
| 產生的圖不對、或滑桿沒作用 | 切到分頁 5（備援檔案）繼續，**不要當場除錯** |
| 它停下來問問題、或要求權限 | 直接回「可以」；不要在台上讀它問什麼 |
| 它跑超過 3 分鐘 | 切備援，說「平常一兩分鐘，今天網路慢」；不要等 |
| 終端機或登入出狀況 | 切備援；後面示範二改用分頁 3 的 GitHub 網頁介面上傳（免費路線） |

**切備援不是失敗，是素材。** 順帶說一句：

> 第一版不完美是正常的。三小時的版本裡有一整段在處理這件事。

## 示範二：存進版本庫並發布（投影片 8，約 2 分鐘）

接續示範一，仍在同一個 Claude Code 工作階段。

| # | 動作 | 說什麼 |
| --- | --- | --- |
| 1 | 對 Claude Code 說：「把這個檔案存進版本庫並發布，做好後告訴我網址。」 | —— |
| 2 | 它 commit、push；切到分頁 3 讓台下看到 commit 出現 | 「剛才那一步就是還原點，之後怎麼改都回得去」 |
| 3 | 打開它給的網址（`你的帳號.github.io/demo-live/sine/`） | 若尚未更新，切分頁 4 並說明部署要等 |
| 4 | **拿出手機打開同一個網址，舉起來** | 投影片 8 的關鍵句 |

**免費路線備援**：Claude Code 若在這裡出狀況，切分頁 3，用 GitHub 網頁 Add file → Create new file 把檔案貼上去
commit——那正是三小時免費版教材的做法，順帶說一句「免費版就是這樣做」。

### 第 7 步是全場最有說服力的畫面，不要省

螢幕上的網址是抽象的，手機拿在手上是具體的。在座每個人都知道
「學生不必登入」代表什麼。

手機建議**先在瀏覽器輸入好網址但不要送出**，示範時按一下即可，不要當場打字。

## 示範三：雙人單字對決（投影片 25，約 2 分鐘）

| # | 動作 | 說什麼 |
| --- | --- | --- |
| 1 | 切到分頁 6 | 「這是同一套流程做出來的，但幾乎不需要學科構造」 |
| 2 | 輸入第一個字（例如 `CRANE`），確定 | 「輸入時不會顯示，所以兩個人可以用同一台」 |
| 3 | 輸入第二個字（例如 `SPEED`），確定 | —— |
| 4 | 猜一次錯的（例如 `ERASE`） | 指著顏色說明：綠是位置對、黃是有這個字母 |
| 5 | 再猜一次 | 讓觀眾看到輪流的機制 |
| 6 | 停在這裡即可 | 「單字範圍可以限定成這一課的生字」 |

### 不要現場找人上台

兩分鐘的段落，請人上台會失控。**你自己輸入兩個字**，說明課堂上是兩個學生輪流即可。
若時間充裕且氣氛適合，才邀請前排兩位。

### 出錯時

這個檔案是現成的，不需要網路，幾乎不會出錯。
真的當掉就重新整理——資料沒有存檔，重整就是新的一局。

## 選配：現場收題（高風險，第二場以後再考慮）

**做法**

1. 入場時每人發一張便條：「寫一個你教學上的小煩惱，一句話。」
2. 示範二結束後（第 8 頁），抽一張，唸出來，當場照示範一的流程做：寫提示詞、產生、存檔、開啟。
3. 成功：這是全場最強的一刻，不必多說。失敗：切備援，說「這就是為什麼三小時裡有一整段在處理失敗」。

**時間**：約 5 分鐘。自立論段挪出——執行時**略過第 13、14 頁**（程式閉環、物理世界斷環），
以第 16 頁的主張直接收束；這兩個觀點於問答時仍可補。時間表其餘不動。

**先決條件**：至少完整跑過一場，對示範一的失敗路徑有把握；備援分頁 5 已開好。
第一場不要做。

**不要做的事**：不要挑題。抽到什麼做什麼——挑題會讓在座的人看出來，反而失去說服力。
抽到明顯做不到的（要登入、要資料庫），當場說「這題超出今天的範圍，是三小時課程裡『這次不做』的那一欄」，再抽一張。那本身也是教材。

## 三個示範的共同原則

1. **不要解釋程式碼。** 一旦開始講程式碼，非資訊背景的老師會判定這是資訊課。
2. **每個示範都要有一個「指著看」的動作**：示範一指三個數值、示範二舉手機、
   示範三指顏色。沒有這個動作，觀眾只看到你在操作電腦。
3. **失敗就切備援，不要除錯。** 除錯會吃掉時間，而且會把全場帶進技術細節。
4. **事前完整跑過一次。** 包含前一天的 Pages 暖機。這四個示範加起來約 13 分鐘，
   佔全場三成，是這場成敗的關鍵。
