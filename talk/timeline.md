# 60 分鐘演講流程表（講者用）

**這份檔案是這場 60 分鐘演講的時間唯一真實來源。** 投影片：`talk/deck.md`（33 頁）。

**準備時請搭配兩份：**
[`script.md`](script.md) 是逐張的講稿（要說什麼），
[`demo-runbook.md`](demo-runbook.md) 是四個示範的操作腳本（手怎麼動）。

## 這場的定位

對象是**種子教師**。這一小時**不安排學員動手**——60 分鐘內處理帳號與登入的風險太高，
而且那不是這場的目的。

| | 這場 60 分鐘 | 他們回去要辦的 3 小時啟動場 |
| --- | --- | --- |
| 目標 | 決定要不要把三小時給同事 | 每個人帶著已上線的第一版離開，之後各自迭代 |
| 形式 | 演講 + 兩段現場示範（講者以自己實際使用的 Claude Code 示範） | 全程動手 |
| 學員需要 | 什麼都不用準備 | 兩個免費帳號，課前完成 |
| 教材 | `talk/deck.md` | `workshop/`（195 分鐘） |

**兩者不是長短版的關係。** 三小時的教材不因為這場而縮減，它是這場的**交付物**。

### 第五次調整：示範改用講者實際使用的工具，演講改為自我示範

**示範改用 Claude Code CLI，在投影機上的終端機執行。** 原 runbook 建議用免費對話介面示範，
理由是台下手上沒有 Claude Code。但講者示範一個自己從不使用的流程，比工具不匹配更傷；
而第 31 頁那門課本來就是用 Claude Code 做的。代價由第 29 頁一句話收掉：
今天示範用付費工具，免費對話介面能做到同一件事，三小時教材就是那個版本。
Claude Code 把「產生檔案」與「存進版本庫、拿到網址」收成連續動作，示範一 11→8、產出處置 9→7，
**多出 5 分鐘**。

**多出的時間給新段落「這場演講本身是怎麼做出來的」（第 26–27 頁）。** 這個 repo 截至 9 月 3 日
有 68 個 commit、64 個帶 Claude 共同作者標記（94%）、65 個檔案、18 天——三份投影片、四個網站、
五個範例、案例頁、整套講師文件。它和第 31 頁是同一種證據但更強：不是「我用它做了一門課」，
是「你眼前的一切」。**第 27 頁的數字會漂，演講前一天要更新**（指令在 script.md 該條）。

**三小時教材的定位隨之改變：從交付物變成其中一個成品。** 第 28 頁不再逐列介紹教材，
改說「可以 fork，但更好的是做你自己的」。第 32 頁的請求相應改為三個動作：
建自己的 repo、用它辦一場啟動場、回傳連結。

bootstrap 的方向也收斂為老師→老師；「學生不需要帳號」仍是產出物的性質，不再是請求的一部分。
三小時教材與免費版預設**都不刪**——免費版仍是回校辦啟動場時的預設，只是演講不再說「請用這套」。

### 第四次調整：讓聽眾的手碰到東西

前三次調整都在改講者說什麼；這次改的是聽眾做什麼——六十分鐘裡聽眾原本從頭到尾是觀眾。

| 改動 | 位置 | 時間來源 |
| --- | --- | --- |
| 開場：講者自身的故事（559 字，約 2 分半），再用 60 秒讓全場用手機開人生導師 | 第 1 頁講稿、第 2 頁 QR | 開場段 3→4 分，自教材段挪出（7→6）；原定位頁的內容併入講稿 |
| 人生導師當「驗收條件」的對照組 | 新增第 22 頁 | 刪去「三個常見提問」，立論 12→11、流程 13→14 |
| 選配：現場收題 | 不佔投影片，見 `demo-runbook.md` | 執行時自立論段挪 4 分，見該節 |

第 22 頁是一個**故意會錯**的示範：問「小孩不聽話」得到談子女孝道的章句，字面命中而方向相反。
它把「先訂定驗收條件」從只有數理科有感的例子，擴到所有科目——多數教學工具沒有數字可核對，
「對」必須由人先定義。

### 第三次調整：加入實際案例

第 31 頁「一學期的實際紀錄」引用 `github.com/htchen/I2P_Python`：
2026 春季一門大學程式設計課的教材，114 個 commit 中 56 個由 Claude 直接署名，
38 個經 Pull Request 合併。**這是全場唯一的實績佐證**，補上先前完全空白的一塊。

框架須嚴守：**不宣稱「非程式背景也能做」**——該課為程式設計課、講者具程式背景，
台下一查即知，硬套會使前段一併失去可信度。應宣稱的是流程撐得起一整個學期的
真實教材，且全程可稽核。完整數據與其他案例置於 `web/cases.html`。

時間來源：刪去立論段的提問頁（13→12 分），移入教材段（6→7 分）。

## 講者事前準備

1. **自己先跑一次兩段示範——用 Claude Code CLI，在要上台的那台電腦。** 知道它這次大概會做什麼、花多久；
   終端機字級放大到後排看得到。
2. **確認 `examples/lunyu-mentor.html` 手機打得開**——第 2 頁全場要掃。
3. **開好兩個備援分頁**：`htchen.github.io/LLM2Life/examples/sine-addition.html`（示範一備援）與
   `.../examples/wordle-duel.html`（投影片 25 要開一局）。使用網址即可，無須先 clone repo。
   現場產生失敗時直接切過去，**不要當場除錯**。
3. **前一天就要建好示範 repo 並啟用 Pages，且確認網址真的打得開。**
   Pages 第一次部署要等 1–10 分鐘，當天才開會在台上開出 404——
   這是整場最大的操作風險，詳見 `demo-runbook.md`。
4. **手機準備好**，示範二最後要用手機打開那個網址給大家看。
5. 最後一張投影片已內含 QR code，不必另外做；白板可再寫一次網址備用。

## 兩段示範的重點

### 示範一（投影片 3–5，8 分鐘）

在 Claude Code 裡貼上提示詞、它寫檔並打開、你拉滑桿。**不要解釋程式碼，也不要解釋終端機。**

它跑的那一兩分鐘台下看得到它讀了什麼、寫了什麼——那正是第 9 頁三項工作裡的第二項正在發生，
講出來。**這個提示詞比一般的長，也較容易失敗**——中間三行是幾何構造，
那正是投影片 24 要回頭指的東西，所以值得冒這個風險。

做完之後的動作比產生本身重要：**拉動兩個滑桿，指著下方三個數值**，
說「兩段相加一直等於 sin(α+β)，我不是在看它漂不漂亮，我在看它對不對」。
這句話在投影片 21（驗收條件）會回來用。

**失敗處理：** 直接開備援分頁繼續。可以順帶說一句「第一版不完美是正常的，
三小時的版本裡有一整段在處理這件事」——這反而是真實素材。

### 示範二（投影片 8，約 2 分鐘）

對 Claude Code 說「存進版本庫並發布，做好後告訴我網址」→ 它 commit、push → 拿到網址 → **用手機打開**。
指著終端機說：剛才那一步就是還原點。免費對話介面做同一件事要自己存檔、自己上傳——三小時教材就是那個版本。

這一段一定要當場做完。沒有它，投影片 7 的三項條件只是宣稱。
手機打開那一刻是全場最有說服力的畫面：**學生不必登入、不必安裝，掃碼就能用。**

## 時間不夠時的取捨順序

依序捨棄，**不要臨場自己抓**：

1. 投影片 12（文明）與 16（脈絡）——保留 14、15、17
2. 投影片 30（適用範圍）
3. 投影片 25（單字對決）——**但語文科教師在座時不要捨**
4. 投影片 24（構造由教師提供）——**但數理科教師在座時不要捨**

投影片 24 與 26 是一組：一個示範學科專業不可取代，一個示範適用範圍不限數理。
兩張都捨，這場就只剩數理色彩。

**任何情況都不要捨：** 投影片 5（驗收）、8（存回 GitHub）、17（主張）、
18（流程與探究歷程對應）、23–25（帶走什麼）、27（這個 repo 怎麼做出來的）。
捨掉 8 或 18，這場就失去了與「已經在用 AI 聊天」的老師之間的差別。

## 最後一段要交代清楚的事

老師離場時必須知道三件事，投影片 27–32 就是為此存在：

1. **今天看到的一切都是這樣做出來的**——commit 歷史公開可查
2. **三小時教材是其中一個成品**：可 fork（CC BY 4.0），但更好的是做自己的
3. **回去做什麼**：建自己的 repo、用它辦一場、回傳連結——`htchen.github.io/LLM2Life/seed-teacher.html`

如果只能講一句話收尾，講這句：

> 今天看到的一切，都是用今天講的方法做出來的。回去做你自己的。
