# 帶回家的小抄

印出來或存書籤。這一頁是三小時裡真正需要記住的東西。

---

## 一、講話的公式

大部分「它做出來的不是我要的」，原因都是**話講太短**。補上這四件事就會準很多：

> **我要做什麼** + **有哪些功能** + **我要看到什麼** + **有什麼限制**

❌ `做一個待辦清單`

✅ ```
做一個待辦清單網頁，單一個 index.html：
可以新增、打勾完成、刪除，資料存在瀏覽器裡。
中文介面，手機上能用。做好幫我打開來看。
```

幾個很值錢的補充句，隨時可以加在後面：

| 想要的效果 | 加這句 |
| --- | --- |
| 不要一堆看不懂的檔案 | `單一個 index.html 檔案就好，不要用任何套件` |
| 做完直接看到成果 | `做好之後幫我在瀏覽器打開來看` |
| 手機也要能用 | `手機上也要能用` |
| 不確定它會怎麼做 | `先跟我說你打算怎麼做，我同意再開始` |
| 怕它做太多 | `只改我說的地方，其他不要動` |

## 二、把大要求切成小塊

Claude Code 一次做得越多，你越難知道是哪一塊出了問題。固定用這個節奏：

> **先拆小塊 → 一次做一塊 → 打開來看 → 親手測試 → commit 存一版**

```text
先把這個需求拆成幾個可以各自驗收的小步驟，只列步驟，先不要動手。
```

```text
現在只做第 1 步。做完幫我打開來看，其他步驟先不要做。
```

每一塊測試通過就 commit。commit 訊息直接寫這一塊做了什麼，例如「加上分類功能」。
這樣 GitHub 的紀錄就是你的工作清單，也是改壞時可以回去的安全存檔點。

> 「小塊」不代表一定要拆成很多檔案。單一個 `index.html` 也可以分成新增、分類、統計、
> 匯出等功能，一塊一塊完成。

## 三、五句救命的話

九成的狀況用這五句就能解決。

```text
請把剛剛的改動還原，回到上一個能正常運作的版本
```

```text
（貼上錯誤訊息）請修好它
```

```text
幫我在瀏覽器打開這個頁面
```

```text
把剛剛測試通過的這一塊 commit 並 push 到 GitHub，commit 訊息清楚寫出改了什麼
```

```text
用我聽得懂的方式解釋你剛剛做了什麼，不要用專有名詞
```

> **最重要的一句是第二句。**
> 看到紅色的字不要慌、不要自己讀——**整段複製，貼回去，說「請修好它」。**

## 四、腦袋裡帶走的三句話

技巧會過時，這三句不會。

> ### 你沒辦法把「自己還沒想清楚的事」外包出去
>
> 你改了三次才對，通常不是因為它笨，是因為**第一次你自己也還沒想清楚**。
> 你腦袋裡有一整套「這還用說嗎」的預設——它不知道。

> ### 看起來對 ≠ 對
>
> 危險的不是它寫出爛東西，爛東西你一眼就看得出來。
> 危險的是它寫出**看起來很對但其實不對**的東西，而且它會**很有自信**地做錯。
> 所以動手前先想：「做好了應該長什麼樣？」

> ### 越難收回的事，越要親眼看過再放行
>
> 改個顏色？讓它做，錯了再改。
> 刪資料、寄信給別人、花錢？**先看過再說。**

驗收前問四件事：

1. **能不能重試或回到上一版？**
2. **做好了，我應該看到什麼？**
3. **錯了誰會看到，代價是什麼？**
4. **有沒有畫面、截圖或實際執行結果可以親眼看？**

## 五、心態（比技巧重要）

- **不滿意就再講一次，不用重來。** 你不會把它弄壞，弄壞了也救得回來。
- **它問「可以嗎」的時候是在保護你。** 看一眼要改什麼，再按同意。
- **它跑很久是正常的。** 它在讀檔案、寫檔案、檢查自己。
- **講得囉唆比講得漂亮有用。** 把你知道的限制先講出來，就不會踩到。
- **紅色的錯誤不是失敗，是下一句話的材料。**

## 六、GitHub 名詞對照

| 你看到的 | 白話 |
| --- | --- |
| repository / repo | 一個會記得所有版本的資料夾 |
| commit | 一小塊測試通過後的安全存檔點，並寫一句「我這次改了什麼」 |
| push | 把本機的存檔上傳到 GitHub |
| Actions | GitHub 借你的雲端電腦，可以按時間自動做事 |
| workflow | 給那台電腦的紙條：幾點做、做什麼 |
| Pages | 把你的網頁變成一個公開網址 |
| branch | 另開一條線改東西，不影響原本的 |

## 七、回家繼續的三個題目

由易到難，做完一個再做下一個：

1. **改你今天做的東西。** 把記帳工具改成你真的會用的樣子——你要的分類、你喜歡的顏色。
2. **改每日摘要。** 換成你真正想每天收到的：你追的網站、天氣、匯率。
3. **做一個只有你需要的東西。** 這個最重要。想一件你每週都要手動做一次的瑣事，
   把它描述給 Claude Code，讓它幫你做掉。

第 3 題卡住的話，先問它：

```text
我每個禮拜都要手動做（描述那件事），很煩。
有沒有辦法自動化？請用我聽得懂的方式給我幾個做法，先不要寫程式。
```
