印出來或存書籤。這一頁是三小時裡真正需要記住的東西。

## 一、講話的公式

大部分「它做出來的不是我要的」，原因都是**話講太短**。補上這四件事就會準很多：

> **我要做什麼** + **有哪些功能** + **我要看到什麼** + **有什麼限制**

❌ `做一個待辦清單`

✅ ```
做一個待辦清單網頁，單一個 index.html：
可以新增、打勾完成、刪除，資料存在瀏覽器裡。
中文介面，手機上能用。做好幫我打開來看。
```

幾個很值錢的補充句，隨時可以加在後面：

| 想要的效果 | 加這句 |
| --- | --- |
| 不要一堆看不懂的檔案 | `單一個 index.html 檔案就好，不要用任何套件` |
| 做完直接看到成果 | `做好之後幫我在瀏覽器打開來看` |
| 手機也要能用 | `手機上也要能用` |
| 不確定它會怎麼做 | `先跟我說你打算怎麼做，我同意再開始` |
| 怕它做太多 | `只改我說的地方，其他不要動` |

## 二、五句救命的話

九成的狀況用這五句就能解決。

```text
請把剛剛的改動還原，回到上一個能正常運作的版本
```

```text
（貼上錯誤訊息）請修好它
```

```text
幫我在瀏覽器打開這個頁面
```

```text
把目前的改動 commit 並 push 到 GitHub
```

```text
用我聽得懂的方式解釋你剛剛做了什麼，不要用專有名詞
```

> **最重要的一句是第二句。**
> 看到紅色的字不要慌、不要自己讀——**整段複製，貼回去，說「請修好它」。**

## 三、心態（比技巧重要）

- **不滿意就再講一次，不用重來。** 你不會把它弄壞，弄壞了也救得回來。
- **它問「可以嗎」的時候是在保護你。** 看一眼要改什麼，再按同意。
- **它跑很久是正常的。** 它在讀檔案、寫檔案、檢查自己。
- **講得囉唆比講得漂亮有用。** 把你知道的限制先講出來，就不會踩到。
- **紅色的錯誤不是失敗，是下一句話的材料。**

## 四、GitHub 名詞對照

| 你看到的 | 白話 |
| --- | --- |
| repository / repo | 一個會記得所有版本的資料夾 |
| commit | 存檔，並寫一句「我這次改了什麼」 |
| push | 把本機的存檔上傳到 GitHub |
| Actions | GitHub 借你的雲端電腦，可以按時間自動做事 |
| workflow | 給那台電腦的紙條：幾點做、做什麼 |
| Pages | 把你的網頁變成一個公開網址 |
| branch | 另開一條線改東西，不影響原本的 |

## 五、回家繼續的三個題目

由易到難，做完一個再做下一個：

1. **改你今天做的東西。** 把記帳工具改成你真的會用的樣子——你要的分類、你喜歡的顏色。
2. **改每日摘要。** 換成你真正想每天收到的：你追的網站、天氣、匯率。
3. **做一個只有你需要的東西。** 這個最重要。想一件你每週都要手動做一次的瑣事，
   把它描述給 Claude Code，讓它幫你做掉。

第 3 題卡住的話，先問它：

```text
我每個禮拜都要手動做（描述那件事），很煩。
有沒有辦法自動化？請用我聽得懂的方式給我幾個做法，先不要寫程式。
```
