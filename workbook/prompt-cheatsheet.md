# 帶回家的重點整理

可以列印或存成書籤，作為課後操作參考。

---

## 一、描述需求的格式

如果結果不符合預期，通常是需求資訊不足。描述時請包含以下四項：

> **我要做什麼** + **有哪些功能** + **我要看到什麼** + **有什麼限制**

❌ `做一個待辦清單`

✅ ```
做一個待辦清單網頁，單一個 index.html：
可以新增、打勾完成、刪除，資料存在瀏覽器裡。
中文介面，手機上能用。做好幫我打開來看。
```

以下補充句可依需求使用：

| 想要的效果 | 加這句 |
| --- | --- |
| 不要一堆看不懂的檔案 | `單一個 index.html 檔案就好，不要用任何套件` |
| 做完直接看到成果 | `做好之後幫我在瀏覽器打開來看` |
| 手機也要能用 | `手機上也要能用` |
| 不確定它會怎麼做 | `先跟我說你打算怎麼做，我同意再開始` |
| 限制改動範圍 | `只改我說的地方，其他不要動` |

## 二、把大型需求拆成小步驟

Claude Code 一次做得越多，你越難知道是哪一塊出了問題。固定用這個節奏：

> **先拆小塊 → 一次做一塊 → 打開來看 → 親手測試 → commit 存一版**

```text
先把這個需求拆成幾個可以各自驗收的小步驟，只列步驟，先不要動手。
```

```text
現在只做第 1 步。做完幫我打開來看，其他步驟先不要做。
```

每一塊測試通過就 commit。commit 訊息直接寫這一塊做了什麼，例如「加上分類功能」。
這樣 GitHub 的紀錄可以作為工作清單，也能在修改發生問題時回到先前版本。

> 「小塊」不代表一定要拆成很多檔案。單一個 `index.html` 也可以分成新增、分類、統計、
> 匯出等功能，一塊一塊完成。

## 三、五個常用提示詞

以下五個提示詞可處理課程中的常見狀況。

```text
請把剛剛的改動還原，回到上一個能正常運作的版本
```

```text
（貼上錯誤訊息）請修好它
```

```text
幫我在瀏覽器打開這個頁面
```

```text
把剛剛測試通過的這一塊 commit 並 push 到 GitHub，commit 訊息清楚寫出改了什麼
```

```text
用我聽得懂的方式解釋你剛剛做了什麼，不要用專有名詞
```

> 遇到紅色錯誤訊息時，先完整複製並貼回 Claude Code，再要求它說明與修正。

## 四、應該記住的三句話

技巧會過時，這三句不會。

> ### 尚未釐清的需求無法完整交給 AI
>
> 修改幾次後才符合需求，通常表示最初有些條件尚未說明。
> AI 不知道你認為理所當然、但沒有寫出的條件。

> ### 看起來對 ≠ 對
>
> 明顯不符合需求的結果容易發現；更需要注意的是**外觀看似正確、實際行為卻不正確**的結果。
> AI 的語氣可能很確定，但輸出仍需要驗證。
> 所以動手前先想：「做好了應該長什麼樣？」

> ### 越難收回的事，越要親眼看過再放行
>
> 調整顏色等可回復的修改，可以先執行再檢查。
> 刪除資料、寄送訊息或產生費用前，應先確認內容與影響。

驗收前問四件事：

1. **能不能重試或回到上一版？**
2. **做好了，我應該看到什麼？**
3. **錯了誰會看到，影響是什麼？**
4. **有沒有畫面、截圖或實際執行結果可以親眼看？**

## 五、操作原則

- **結果不符合需求時，補充條件後再修改。** 不需要從頭開始。
- **Claude Code 詢問權限時，先確認操作內容，再按同意。**
- **處理時間較長時，查看它正在讀取或修改哪些檔案。**
- **把已知限制寫完整。** 完整比簡短更重要。
- **錯誤訊息是修正問題所需的資訊。**

## 六、GitHub 名詞對照

| 你看到的 | 白話 |
| --- | --- |
| repository / repo | 一個會記得所有版本的資料夾 |
| commit | 一小塊測試通過後的安全存檔點，並寫一句「我這次改了什麼」 |
| push | 把本機的存檔上傳到 GitHub |
| Actions | GitHub 借你的雲端電腦，可以按時間自動做事 |
| workflow | 給那台電腦的紙條：幾點做、做什麼 |
| Pages | 把你的網頁變成一個公開網址 |
| branch | 另開一條線改東西，不影響原本的 |

## 七、回家繼續的三個題目

由易到難，做完一個再做下一個：

1. **改你今天做的東西。** 把記帳工具改成你真的會用的樣子——你要的分類、你喜歡的顏色。
2. **改每日摘要。** 換成你真正想每天收到的：你追的網站、天氣、匯率。
3. **做一個只有你需要的工具。** 想一項每週都要重複處理的工作，
   把流程描述給 Claude Code，請它協助自動化。

第 3 題若需要協助，可先使用以下提示詞：

```text
我每個禮拜都要手動做（描述那件事），希望減少這項重複操作。
有沒有辦法自動化？請用我聽得懂的方式給我幾個做法，先不要寫程式。
```
